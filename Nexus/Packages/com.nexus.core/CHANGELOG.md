# Changelog

All notable changes to the Nexus Core package will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This is the changelog of the core, its adapter packages (`com.nexus.iap.unity`, `com.nexus.firebase`), the
packages split from it (`com.nexus.fsm`, `com.nexus.dots`) and the history of `com.nexus.ads.admob`'s legacy
`AdMobAdapter` until issue #14 removed it; the ad package family has its own, `com.nexus.ads/CHANGELOG.md`. The package version in `package.json` is the released version;
everything under Unreleased is in the repository but not yet in a tagged package.

## [Unreleased]

### Added
- **Resolving a runtime `Type` through `IResolver`** (issue #148): `Resolve(type)` and `TryResolve(type, name = null)` do what the generic forms do, the parent contexts and named bindings included. A game that checked a list of types resolved them through reflection, and `typeof(IContext).GetMethod("TryResolve")` finds nothing since `IContext` inherits the method from `IResolver`: RingFlow's DI integrity check (`GameplayLifecycle.cs:541`) would stop checking without a word at its re-pin. `Context` and `MockContext` implement both; MIGRATION lists the interface.
- **Binding a type to a delegate from the builder** (issue #149): `IContextBuilder.BindFactory<T>(create, lifetime)` and a named form, for a service built from a value read in `OnConfigure`. PuzzleGame reflected into `ContextBuilder._container` to reach `NexusDI.BindFactory`. The lifetime is required and is the one `Bind<T>(Lifetime)` gives: Singleton runs the delegate once and binds it on the root container, Scoped once for the context, and the container disposes either instance; Transient runs it on every resolve and owns nothing. The container's `BindFactory<T>(factory)` keeps its transient meaning, and its new `BindFactory<T>(factory, lifetime)` overloads back the builder. The delegate runs at the first resolve and gets no [Inject] members. When a factory's delegate throws, of either API, the error log now names the bound type and the exception reaches the caller unchanged. EditMode `ResolverAndFactoryBindingTests` (3); full EditMode run on the change: 711 total, 710 passed, 0 failed, 1 skipped (`Nexus/artifacts/di-148-149/edit.xml`).
- **`BigDouble.Pow(value, power)`** (issue #196), computed in log10 space so the result can pass a double's range: `BigDouble.Pow(1.15, 6000)` is about 1.5e364 where `Math.Pow` returns infinity. A result above `MaxValue` saturates; a negative value to a fractional power, or a non-finite power, throws `ArgumentOutOfRangeException`, and zero to a negative power `DivideByZeroException`. The owner's decision on non-finite input named `Pow` as the way out, and `BigDouble` had none.
- **`SpendRefundedSignal` and `EconomyRefusal`** (issue #196). When the network validator refuses a spend the economy had already applied, the amount comes back as before and the service now fires `SpendRefundedSignal` (currency, `Amount` saturated to `long`, exact `BigAmount`, the spend's reason) with `FireThreadSafe`, so a game can take back what it granted; the refund changed the balance with no event. The new `Spend` and `SpendBig` overloads with `out EconomyRefusal` say why a spend returned false: `InsufficientBalance`, `InvalidCurrencyId` or `Disposed`. A BigDouble refund now logs the same `WarnAlways` line as a long one.
- **Custom keys and log lines on crash reports** (`com.nexus.firebase`, issue #199): `ICrashReporter.SetCustomKey(key, value)` and `Log(message)`, sent by `FirebaseCrashReporter` to `Crashlytics.SetCustomKey` and `Crashlytics.Log` and kept by `MockCrashReporter` (`Keys`, `Logged`). A crash from a shipped player arrived with no level, build flavour, consent state or last screen; Wickling's studio review named it a GameContainer item. Services initialize one by one in bind order, so `CrashContext` holds what a service bound before the reporter sets until the SDK is ready (each key with its last value, the newest 64 lines) and drops it when the SDK is unavailable; an empty key is warned in every build. No consumer game implements `ICrashReporter`. EditMode `CrashContextTests` (2 cases); the adapter compiles against Firebase Unity SDK 14.1.0 in `Nexus/artifacts/firebase-20261031/FirebaseConsumer`.
- **`ApplicationQuitSignal` and `LowMemorySignal`** (issue #199), fired by `Root` on its context's bus from `OnApplicationQuit` and `Application.lowMemory`, synchronously and only once the context has started, as `ApplicationPauseSignal` is (#70). Gigawatt and ChipCrisis hooked both themselves. Android and iOS normally end a backgrounded app without a quit call, so a save that must survive stays on the pause signal (`CANONICAL-PATTERNS.md`; `OfflineTimeCalculator.RecordQuitTimestamp` names both signals). PlayMode `ContextSignalsTests.QuitAndLowMemoryReachTheContextOnlyAfterItHasStarted`.
- **The UI Toolkit screen stack** (issue #76, ADR-0003), in parts; user documentation in `docs/SCREEN_STACK.md`, and `CANONICAL-PATTERNS.md` names it the screen API for new UI, beside `UIManager` for uGUI screens.
  - A read-only observable: `IReadOnlyObservableProperty<T>` (`Value`, `OnChanged`, `RemoveOnChanged`), which `ObservableProperty<T>` implements, and a `Mediator.TrackObservable` overload that takes it. A service exposes state that it alone sets (the coming screen stack's `Current`) without a public setter, and a mediator still watches it with automatic cleanup on `Unbind`. Both are additions; no existing call changes overload, since an `ObservableProperty<T>` argument still binds to the class overload. Host harness `TeardownLeakSuite` TL4: one change seen while bound, none after `Unbind`. With an overload that subscribes without tracking, TL4 fails.
  - The history and the back chain, without the engine: the public `ScreenRoute`, `BackResult`, `RootBack`, `BackOrder` and `IBackRouter`, and the internal `ScreenHistory` and `BackChain`. A screen is shown while it holds the last entry of its layer, so the screen below on the same layer is hidden and lower layers stay shown. A press runs the `BeforeScreens` steps, then the top screen's back (its own handler, then its block, then a pop), then the `AfterScreens` steps, then the root behaviour, and stops at the first one that takes it. Host harness `ScreenStackSuite` SS1-SS8: Gigawatt's `UiRegressionSuite` navigation cases, one handler per press, the step order and the three root behaviours, the layer rule, steps removed during a press, and a screen that changes the history while it is shown. Each of five rules, taken out of the code, fails its case: the top screen's own handler before its block (SS3, SS4), the end of a pending press-again after a handled press (SS5), the layer rule (SS6), skipping a step removed during the press (SS7), and no screen call inside another (SS8). GCAudit GCA10: 5000 polls without a press allocate 0 B (harness, with a fake input service).
  - The engine side (`Runtime/Services/UI/Stack/Toolkit/`). `ToolkitScreen` is a `View` that registers with its context's stack when it binds, is shown and hidden by `display` and the class `nexus-screen--shown` (never by deactivation; a deactivated or disabled screen leaves the history and is hidden) and hears a back press first while on top (`OnBack`). `ScreenStack` is one service behind `IScreenStack` and `IBackRouter` (`builder.BindServiceInterfacesAndSelfTo<ScreenStack>()`); its `...Async` calls complete when the root's USS transition ends, timed from the resolved style because `TransitionEndEvent` does not come for a transition that never ran, and at once without one or under `ReducedMotion`. A child context's router joins its parent's chain as a `BeforeScreens` step; only the top router reads `IInputService` "Cancel" and runs its root behaviour, once per frame from its own driver, so back still closes a screen while `TickService` is paused, and a stack in an unrelated context logs an error instead of reading the key a second time. `SafeArea.Pad` pads an element by the device's safe area in panel units. The core's `package.json` declares `com.unity.modules.uielements` 1.0.0. Locked by PlayMode `ScreenStackTests` and `ScreenStackBackKeyTests` (12 cases, one of them a transition that ends while `Time.timeScale` is 0), EditMode `SafeAreaTests` and harness SS9-SS10; four faults found while building (a call from a screen's show handler dropped the outer call's transitions, a screen shown again with other arguments waited for a transition that never ran, a disabled screen's document stayed shown, a disabled `UIDocument` left the running transition's task pending and its rebuilt root without the screen's state) were fixed, and the mutant of each fix and of the state given to a root that appears after the bind fails its test.
  - `ToolkitPanelInput`: UI Toolkit input through the `EventSystem` without uGUI's allocation on every frame (ADR-0003 decision 7). uGUI 2.6.0's bridge retries each panel's event objects on every frame and allocates 32 B per panel doing it, also without a touch. The component, on the `EventSystem`'s GameObject, turns `PanelInputConfiguration.autoCreatePanelComponents` off (adding a configuration when the scene has none, and giving the previous value back when disabled) and makes each panel's `PanelEventHandler` and `PanelRaycaster` once: for the documents of each scene that loads, for every `ToolkitScreen` (a screen's root now announces its document to it) and for the documents passed to `Attach`. PlayMode `ToolkitPanelInputTests` (5): one event object per `PanelSettings` that the `EventSystem`'s raycast hits; 0 `GC.Alloc` samples over 10 `EventSystem` frames after the component took a panel from the bridge; a screen made later; the configuration given back when disabled; a panel whose objects went with the last scene's `EventSystem`. Four mutants each fail their test; a fifth, ownership by parent instead of identity, survives because the bridge drops its objects as soon as the configuration turns it off. On 2311DRK48G (Android 16, Unity 6000.6.7f1, a development IL2CPP player): 0 B per frame with the component, touched or not, against 32 B per frame without it.
- **Firebase in one binding call, collection off in the manifest** (`com.nexus.firebase`, issue #78): `FirebaseBindings.Bind<TConsent>(builder)` binds `IAnalyticsService`, `IRemoteConfigService` and `ICrashReporter`, the Firebase service of each installed SDK in a player and the mock in the editor (since #171 a player without the SDK gets the `Unavailable*` services, never a mock), and the game's consent reader only where a Firebase service reads it (otherwise a `NotRequired` mock consent). EditMode `FirebaseBindingsTests` (3).
- **Pause holds for screens and ads that open over each other** (issue #77): `ITickService.HoldPause()` returns a handle; ticking stays paused while any handle is held or the `IsPaused` flag is set, and resumes when the last handle is disposed (disposing twice is harmless). One `IsPaused = false` from a closing ad no longer resumes a shop that is still open; games kept their own counted pause service for this. PlayMode `TickServiceTests.TickingResumesOnlyWhenEveryPauseHoldIsReleased`.

A paused `TickService` (its `IsPaused` flag or a `HoldPause` handle) ticks only these; gameplay stays an `ITickable`. A marker interface, not a new `ITickService` method, so no fake tick service changes.

### Changed
- **Breaking: `BigDouble` throws on NaN and infinite input** (issue #196, the owner's decision of 2026-11-01). Both constructors, and so the implicit conversion from `double`, throw `ArgumentOutOfRangeException` as division by zero throws, instead of turning the value into 0: `BigDouble gold = baseIncome * Math.Pow(1.15, level)` became 0 when the double overflowed. Use `BigDouble.Pow` (Added). `SecureObservableBigDouble` treats a stored copy that decodes to a non-finite mantissa as a canary mismatch, so an edited payload still takes the tamper path instead of throwing out of `Value`.
- **Breaking: an economy amount outside the method's range throws** (issue #196, the owner's decision of 2026-11-01). `Spend`, `Earn`, `SpendBig` and `EarnBig` take a positive amount; `CanAfford`, `CanAffordBig`, `SetBalance` and `SetBigBalance` a nonnegative one; any other amount (zero where a change is required, negative, NaN, infinite) throws `ArgumentOutOfRangeException`. Before, `Spend(id, -50)` returned true and spent nothing, `Earn` ignored a negative or zero amount, `SetBalance(id, -5)` set 0, and `CanAffordBig` and `SpendBig` returned false for the inputs `EarnBig` threw on. `SpendBig` with a validator that is not an `INetworkBigEconomyValidator` throws `NotSupportedException`, as `EarnBig` and `SetBigBalance` did, instead of a false a caller could not tell from an insufficient balance. `IEconomyService` has two new members (the refusal overloads); a class that implements it adds them (MIGRATION.md). The Nexus window's Casual Services amount field no longer goes below 1.
- **Breaking: `IIapService.UnrequestedPurchase`** (issue #204), with the adapter capability `IIapUnrequestedPurchaseAdapter` and the delegate `UnrequestedPurchaseHandler(productId, transactionId)`. A class that implements `IIapService` adds the event (MIGRATION.md). `IapService` subscribes to the adapter only while the game has a handler, so an adapter can tell that nothing grants a purchase. `MockIapStoreAdapter` implements it (`ReportUnrequestedPurchase`). `MonetizationServiceTests.UnrequestedPurchase_ReachesTheAdapter_OnlyWhileTheGameHandlesIt`.
- **Breaking: `IObjectPoolService.Prewarm` and `PrewarmAsync` have no `parent` parameter** (issue #184). It set the parent of the pool's own root, so inactive instances died with that object. A pool's inactive instances now always wait under the service's root; the `parent` of `Spawn` applies to the active instance only. The migration guide has the step.
- **Breaking: `IIapService.GetOwnership(productId)` and `IIapStoreInfoAdapter.OwnershipKnown`** (issue #183). `IsProductOwned` was false both for "not owned" and for "the store has not answered yet" (no store, offline, before Play Billing returned purchases, a failed purchase fetch), and nothing could tell them apart. `GetOwnership` answers `Owned`, `NotOwned` or `Unknown`; `IsProductOwned` keeps its meaning (true only when owned). `UnityIapAdapter.OwnershipKnown` turns true when a purchase fetch answers, the testing kit's `MockIapStoreAdapter` after `Initialize` (`SetOwnershipKnown(false)` keeps it unknown). An adapter without store info is known once its `Initialize` answered true. A class that implements `IIapService` or `IIapStoreInfoAdapter` adds the member; no known game does.
- **Breaking: `UICanvasSystem.UpdateLayerInteractivity` is replaced by `SetModalOpen(bool)`, and `ReleaseWithoutDestroy` is removed** (issue #185). `UIManager` calls them; no known game does. `IUIAssetProvider.ReleaseWindow` is now called, on the main thread, possibly with an instance that is already destroyed; the built-in `ResourcesUIAssetProvider` handles that. The migration guide has the step for a custom provider.
- **Every button in the Setup section does what it says** (issue #193). The Setup Wizard is the section's start page. It generates the starter scene; the button is disabled, with the reason, once the starter files exist. It imports each package sample in place (`Sample.Import`), leads an existing project to the Context Wizard, and opens the integration guide, the quick start, Getting Started, Troubleshooting and this changelog, in Turkish when the Nexus window's language is Turkish and a translation exists. Its "Install Nexus" and "Open Dashboard" steps, which always showed done, and the progress bar they filled are gone. The Context Wizard creates a context: `<scope tag>ContextData.asset` and a `[<scope tag>_Root]`, set up before it activates, with the parent Root chosen by position rather than by name. It generates services, view/mediator pairs and signal/command pairs into a scripts folder under Assets that is kept across the recompile, and each generator names the files it wrote and the line to add to `OnConfigure`.
- **One Nexus menu and one window in four sections** (issue #193). The top-level **Nexus** menu opens the window (**Open Window**, `Ctrl+Shift+N`) and each of its sections, **Status**, **Setup**, **Architecture** and **Live**, and holds every other package menu item: Generate AOT Binder, Auto-Generate AOT on Script Reload, Validate Architecture, Code Health Analyzer (was `Window/Nexus/`), Run System Diagnostic Audit, Run Play-Mode Chaos Fuzzing Test, Scene Overlay (was `Tools/Nexus/`) and Editor Settings; `GameObject/Nexus/` keeps the create items. Every tab names its section (`INexusEditorPlugin.Category`: `cat_status`, `cat_setup`, `cat_architecture` or `cat_live`, `NexusWindow.Sections`); a third-party plugin with another category is listed after them, and `Ctrl+1..9` follow the sidebar. The window opens on the tab that was open, also after a recompile, or on the first tab of Status. `NexusWindow.Open(pluginId)` and `OpenSection(category)` open it from code, and the inspectors' button calls `Open()`. A plugin's `OnEnable` and `OnDisable` now bracket each view it builds, and only the shown tab is enabled (every tab's `OnEnable` ran when the window opened). A plugin type without a public parameterless constructor is skipped instead of failing the discovery of all of them. EditMode `NexusWindowTests` (5) build the window with `CreateInstance`, so no window opens; `EveryTab_BuildsItsView_EachTimeItIsOpened` replaces nine tests that ran one plugin's methods and asserted nothing else, and the window smoke test that opened a real window.
- **The Architecture tab maps the game from its code** (issue #193). One tab replaces Explorer, Graph, Type Analyzer and the Game Manager's type lists. It lists the signals, commands, services, models, views and mediators the game's assemblies declare (the assemblies that reference Nexus, without the Nexus packages; the map is rebuilt after each compile). A signal is the `TSignal` of an `ICommand<T>` or `IAsyncCommand<T>`, or a type `[SignalHandler]` or `[CompositeSignalHandler]` names; no type is a signal by its name. For the selected type it shows the signals it handles or the commands that handle it, the members Nexus injects into it (`[Inject]` and `[OptionalInject]` fields and properties, `[Inject]` methods, base classes included, and the injection constructor) and the members in the game's code that receive it, a service's interfaces and a view's mediators, with a button that opens its script. In Play Mode it adds the handlers the running contexts bind, with their scope tag, mode and priority, and the fire form. The graph draws each signal with its commands, one node per command type, lights the nodes the trace reports, and opens a node in the map on a double-click. EditMode `ArchitectureMapTests` (3). Full runs on the change in batch mode: EditMode 709 / 708 / 0 / 1, PlayMode 289 / 287 / 0 / 2 (`Nexus/artifacts/editor-193/full-edit-193p3.xml`, `full-play-193p3.xml`).
- **One context view in the Live section** (issue #193). The Context Inspector replaces the Hierarchy and Game Manager tabs and the Dashboard's runtime card. Its left pane lists the running contexts as a parent/child tree, and a click selects one. ### Performance
- **Generated-bindings comparison** — `tools/nexus-comparison` has a second configuration (`-Generated`: Nexus's generated binder, VContainer's source-generated injectors built from the pinned commit; both verified at runtime) on host, in the Unity Mono player and on the Android device, next to the reflection configuration. Measured 2026-10-15 (`docs/PERFORMANCE_COMPARISON.md`, runs `after-reset-android-006` and `generated-android-002`): on the device the generated factories cut Nexus's transient three-node graph from 5.5 to 2.2 µs; VContainer's injectors reach 1.0 µs, Reflex (no constructor generator) stays at 4.0 µs; cached resolve stays 36.5 ns against 142 (VContainer) and 213 (Reflex).

Caching transient bindings in the generic fast cache was tried the same day and reverted: it tripled cached resolve on the IL2CPP device (31 → 94 ns, run `after-fastslot-android-005`) and bypassed the resolve counter.
- **Transient resolve and container startup** — the static lookups a transient resolve made per object (generated factory, injection metadata, generated injector, three dictionaries and a `HashSet` of tuples for cycle detection) are now cached on the binding and refreshed through a generation counter that every static-cache change bumps; cycle detection uses a thread-static array stack; `Resolve`/`TryResolve` share one single-lookup core and the fast cache is consulted only for singletons; the profiler marker exists only under `ENABLE_PROFILER`. A new container no longer allocates its pending-injection table, lazy-service queue, construction guards or singleton tracking until first use, `_bindings` is sized for a few locks, singleton tracking is one creation-ordered unique list and an empty container disposes without bookkeeping. Measured 2026-10-15 (`docs/PERFORMANCE_COMPARISON.md`): Unity 6000.5.6f1 Mono player transient three-node graph 1115 → 515 ns (Reflex 580), register/build/first resolve 13353 → 5048 ns (Reflex 5367); host 554 → 228 ns and 2494 ns / 5768 B → 1079 ns / 1768 B. ### Fixed
- **`BigDouble` value-equality contract (B1/B2/Or3)** — `Equals` previously compared mantissas with a `1e-12` tolerance while `GetHashCode` used the raw `Mantissa` and `CompareTo` used the `double` default comparison, so equal values could hash differently and an `Equals`-positive pair could `CompareTo != 0` (breaking `SortedSet`/`Dictionary`/sorting invariants). `Equals` is now exact (`Exponent == other.Exponent && Mantissa == other.Mantissa`), `GetHashCode` stays `HashCode.Combine(Mantissa, Exponent)` (now consistent), and `CompareTo` gained early zero/sign branches plus exact `Mantissa.CompareTo`. `operator *` / `operator /` also saturate exponent arithmetic (`SaturateAddExponent`/`SaturateSubExponent`) so a huge product no longer overflows the `long` exponent and silently corrupts the value.
- **`GameSaveManager` main-thread context capture (İ2)** — `_mainThreadContext` was captured in a field initializer (`= SynchronizationContext.Current`) at *type-load* time, when `SynchronizationContext.Current` is still null, so `LoadAsync` could never re-enter the Unity main thread. It is now a lazy `MainThreadContext => _mainThreadContext ??= SynchronizationContext.Current` accessed at first `LoadAsync` call (guaranteed on the main thread), fixing the dead capture.
- **`NexusDI.Dispose()` fire-and-forget ordering (İ3)** — async singletons were disposed one fire-and-forget task per instance (`_ = instance.DisposeAsync()`) launched in parallel with no ordering, so registration-dependency order was lost and continuations could re-capture the disposing thread's `SynchronizationContext`. `Dispose()` now collects `IAsyncDisposable` instances and runs them through a single ordered thread-pool chain `DisposeAllAsyncInBackground` (sequential `await ...ConfigureAwait(false)` per item with per-item error capture); the deterministic `DisposeAsync()` path remains for callers that can await.
- **`ContextLifecycleOrchestrator` await re-capture (İ3)** — `StopAsyncInternal` now `await ...ConfigureAwait(false)` so the stop continuation stays on the thread pool instead of hopping back to the caller's context.
- **Recovery abort exception identity (İ4)** — the recovery engine's Abort / retry-limit throws were plain `InvalidOperationException` and the strategy-failure `catch` filtered on `InnerException == ex` object identity, which misfires when a strategy legitimately wraps the original error. A typed `NexusRecoveryAbortException : InvalidOperationException` (preserving the existing catch/assert contract) is thrown by both paths and the filter now matches on type (`when (!(strategyEx is NexusRecoveryAbortException))`).
- **`GameStateMachine` cancellation terminal state (Or1)** — a bare `catch (OperationCanceledException)` in the error-state recovery path left `_currentState` stale after a cancelled recovery. It now reaches the same terminal `null` state (guarded by the transition sequence) as the inner-exception path, preventing a stale "failed-from" state leak.
- **Anti-Cheat Integrity Canary (`SecureObservableProperty.cs`)**: Fixed dead-code branch in tamper detection so canary failures log security warnings and reset tampered values to defaults.
- **Encrypted Storage Seed Exception Logging (`EncryptedStorageService.cs`)**: Replaced bare `catch` in seed decoding with explicit `catch (Exception ex)` and warning log before fallback seed regeneration.
- **Command Injection Performance (`CommandRegistry.cs`)**: Optimized signal injection setters using compiled `System.Linq.Expressions` to eliminate `FieldInfo.SetValue` reflection overhead in hot paths.
- **Service Dependency Property Injection (`NexusService.cs`)**: Changed `Context` and `SignalBus` property setters from `private set` to `protected set` for property injection compatibility.
- **Domain Lifecycles Execution (`ContextLifecycleOrchestrator.cs`)**: Enabled dual execution of `IAsyncStartable` and `IStartable` (and stoppable equivalents) when a domain object implements both contracts.

### Security
- **DI validation runs in ALL build targets (A10)** — the Configure-time `ContextBuilder.Validate()` call was previously compiled out under `UNITY_EDITOR`, so production builds silently skipped every check (missing dependencies, constructor explosion, and the A8 captive-dependency rule) and left `[Inject]` fields null with no diagnostic. Validation now runs in every build, is logged (never throws), and can be disabled for projects that intentionally defer bindings past Configure via the new `ContextBuilder.ValidateOnStartup` flag (default `true`).
- **ErrorCollection grouping counters bounded (A10)** — `s_errorGrouping` (unique `category:message` → count) previously grew without bound even though the error bag is capped at `s_maxErrors`, so long sessions with dynamic error messages (URLs, ids, filenames) leaked memory. When unique keys exceed 4096 the counters are rebuilt from the retained bag; `Count` now reflects occurrences among retained entries rather than cumulative-ever.
- **Async in-flight overflow throws in ALL builds (A9)** — `CommandExecutor`'s `MaxInFlightAsyncCommands` guard previously logged and silently dropped the command in Release while the caller's async chain completed "successfully"; it now throws `NexusAsyncOverflowException` unconditionally (same principle as the A8 reentrancy guard), and the guard is unified into a single `EnterAsyncInFlight()` used by all four async dispatch paths — including composite async commands, which previously bypassed the cap entirely.
- **NetworkMonitor latency history is thread-safe (A9)** — `s_latencyHistory` and the shared `ConnectionStatus` were written from network/background threads and read from the game/editor thread on a plain `Dictionary` (the same BUG-17 race `PerformanceMonitor` already fixed). - **Reentrancy guard throws in ALL builds (A8)** — `SignalBus` no longer silently returns on `MaxStackDepth` overflow in Release/development-less builds; the `#if UNITY_EDITOR || DEVELOPMENT_BUILD` guard was removed from both the sync and async dispatch paths, so a runaway signal chain now always throws `NexusReentrancyException` (skill checklist §7) instead of hiding state corruption.
- **Atomic save writes everywhere (A8)** — `GameSaveManager` now publishes saves with a single overwrite-rename (`File.Replace`, fallback `File.Move`) instead of the delete-then-move pair that left a crash window where the only good save was already deleted (skill checklist §4.1).
- **Non-blocking teardown (A8)** — `Context` now implements `IAsyncDisposable` (`DisposeAsync()`); the synchronous `Dispose()` path no longer blocks the Unity main thread on `IAsyncDisposable` singletons — async disposal is scheduled on the thread pool with error capture (skill checklist §3.1). Callers that can await should prefer `await context.DisposeAsync()`.
- **Hardware-tick offline anti-cheat (A8)** — `OfflineTimeCalculator` now stores a hardware monotonic tick (`Stopwatch.GetTimestamp() * 1000 / Stopwatch.Frequency`, ms since boot) alongside the wall clock and clamps offline rewards to the hardware-measured elapsed time, closing the forward-clock hole (skill checklist §4.1). On reboot (monotonic reset) it falls back to wall-clock-only validation, still capped.
- **Captive-dependency validation (A8)** — `ContextBuilder.Validate()` now reports `DiValidationIssueType.CaptiveDependency` when a singleton service captures a transient (non-singleton, non-factory) dependency in its constructor or `[Inject]` members (skill checklist §2.2).

- `NetworkSignalHistory` prune paths rewritten from backwards `RemoveAt` loops (O(N²)) to single-pass in-place compaction — `Prune` and `RemoveSignalsAfter` are now O(N) and zero-allocation, preserving the 0-GC steady-state guarantee.
- `Prune(int tick)` parameter renamed to `Prune(int confirmedTick)` across `INetworkSignalHistory`, `NetworkSignalHistory<T>`, `INetworkModelSnapshotHandler` and `NetworkModelSnapshotHandler<TState>` for naming consistency with `PruneHistory(int confirmedTick)`. Positional callers are unaffected; only consumers using the named argument `Prune(tick: …)` would need to update.
- `Root.Start` now guards the post-await main-thread invariant: if lifecycle initialization resumes on a worker thread (user code calling `ConfigureAwait(false)`/`Task.Run` in an environment without a `SynchronizationContext`), the root logs a clear error and disposes the context deterministically instead of touching Unity API from a non-main thread.
- `GameStateMachine.ChangeStateAsync` race — concurrent transitions now serialize via a monotonic sequence: a superseded transition aborts at its next await instead of clobbering `_currentState` or running `OnEnterAsync` (previously two states could end up active). Cancellation sources are disposed by their owning transition in `finally`, so a state holding the old token can no longer hit `ObjectDisposedException`.
- `LocalizationService.FormatRTLIfNeeded` reverses by grapheme cluster (`StringInfo.ParseCombiningCharacters`) instead of raw UTF-16 code units — surrogate pairs (emoji) and combining marks survive RTL reversal.
- `TickService` register paths are deferred to a dirty flag: N registrations in one frame produce exactly one snapshot rebuild instead of one `ToArray()` per call (spawn/despawn storms). Unregister stays immediate so destroyed tickables never tick again.
- `NexusRuntime.Reset()` deadlock fix using snapshot-then-dispose pattern to dispose contexts outside locks during Play Mode transitions.
- Pure context lifecycle duplication — `CreatePureContextAsync` now routes through `Context.InitializeLifecycleAsync`.
- `SignalBus.BroadcastCrossContext` global registry access now abstracts cleanly via `IContextResolver`.
- Plugin discovery failures (`ReflectionTypeLoadException`) now render diagnostic details directly in the `NexusWindow` UI.
- `TracerPlugin` live trace state leaks — `_hasLiveEvents` and queues now reset cleanly in `OnDisable`.
- `DashboardPlugin` action card double-click bug — removed duplicate `MouseDownEvent` callback.
- `DashboardPlugin.QuickFind` keystroke lag — implemented static `s_typedCatalog` scanning cache with 200ms input debounce.
- `GameManagerPlugin.FireTestSignal` reflection overhead — added `s_fireMethodCache` for `MethodInfo` caching.
- `TracerPlugin` CS0411 generic callback type inference compile error fixed by specifying `EventCallback<MouseDownEvent>` explicitly.

### Fixed (Runtime adversarial review)
- PerformanceMonitor `s_samples` queue is now bounded (2000 samples) and history is a FIFO `Queue<float>` — previously the sample queue grew forever between `ClearHistory` drains, leaking managed heap (observed climbing to ~800 MB).
- `PerformanceMonitor.UpdateFrameMetrics` throttled to ~10 Hz (6-frame cadence) — per-frame sampling created ~180 allocations/sec of GC churn that spiked FPS every few seconds.
- `PerformanceMonitor` history is a bounded FIFO `Queue<float>` (O(1) dequeue, capped at `MaxHistorySize`) that never leaks regardless of recording state; only the sample queue and event notifications are gated on recording.
- `NexusDI` field/property injection and clearing now use compiled Expression-tree setters with a reflection fallback (AOT/IL2CPP-safe); the repeated setter-or-reflection branches were consolidated into shared helpers.
- `NexusDI` setter compile failures are logged once per type (was a silent `catch {}`) instead of being swallowed.
- `NexusVisualization.UpdateSparkline` reuses its bar children across refreshes instead of `Clear()`+re-adding hundreds of `VisualElement`s every 0.5 s while playing.
- `PerformanceDashboardPlugin` stat-row cache is cleared when the view/container is rebuilt or the plugin is disabled, preventing stale detached rows from leaving the summary card empty after a window reopen.
- Generic-only recovery fallback commands (`ICommand<TSignal>` / `IAsyncCommand<TSignal>` without the non-generic interface) were silently skipped by the object-based dispatch paths. They now execute via cached reflection dispatchers.
- Sync recovery error handler no longer dispatches async-only fallback types (which would throw and re-enter the same strategy decision, recursing forever) — they are rejected and treated as `Skip`.
- `RegisterCompositeCommand` now rejects duplicate and null signal types up front (a duplicate would set the same mask bit twice and the trigger could never fire).
- `NexusService<T>` double-dispose — `NexusDI.Dispose`/`DisposeAsync` now skip `INexusService` singletons (their lifecycle is owned by the Context, which calls `OnDispose()` exactly once, including lazy services resolved outside the eager `ServiceTypes` list).
- Lazy services first resolved during `OnStartAsync` now still receive `InitializeAsync` (second lazy drain after `OnStartAsync`).
- `CommandPool` double-return guard — an instance already in the pool is discarded instead of being pooled twice.
- `ContextBuilder.Validate()` now validates concrete implementations (`Bind<TInterface, TImplementation>`), previously only interface keys were checked, and no longer flags `LazyInjection<T>` fields (constructed directly by the injector).
- `SignalBus` handler/subscription read-copies are `volatile` with deep-copied snapshots; `FireAsyncAndForget` no longer surfaces `OperationCanceledException` during teardown; dead subscription nodes are swept immediately when not dispatching.
- `WindowManager.IsWindowOpen`/`GetWindow` now use a bounded 50 ms wait instead of `Wait(0)` — a briefly-held semaphore (background async open/close) no longer yields a false "window closed" that could trigger duplicate opens.
- `ObjectPoolService.DespawnAfter` now guards timers with a per-instance spawn-session generation — an instance manually despawned and re-spawned before the timer fires is no longer yanked out of the scene by the stale timer.
- `EncryptedStorageService.SaveKeyToDisk` retries the delete+move swap up to 3 times on `IOException` (Windows file-handle propagation: antivirus/indexer), instead of failing a save when the destination handle lingers.
- `CommandPoolManager.GetCommand` no longer allocates a closure on every call — the pool factory delegate is cached once per manager (hot-path allocation-free; also avoids the `GetOrAdd<TArg>` overload that is unavailable on .NET Standard 2.0).

## [0.4.0] - 2026-07-18

Breaking changes are described in `MIGRATION.md` ("Version 0.3.2 → 0.4.0").

### Changed
- `NEXUS_DEBUG` is opt-in: it is no longer auto-enabled through a version define; enable it in Scripting Define Symbols or from the Tracer plugin. Without it the Tracer dashboard falls back to the production metrics ring buffer.
- Priority semantics documented as implemented: higher priority values run first (documentation and attribute text only; no sorting change).
- `BindCommand`/`BindAsyncCommand` reject `ExecutionMode.Composite` with `ArgumentException`; composite triggers use `[CompositeSignalHandler]` or `SignalBus.RegisterCompositeCommand`.
- `[SignalHandler]` discovery and build validation recognise classes that implement only the generic `ICommand<T>`/`IAsyncCommand<T>`; a `[SignalHandler]` type implementing neither logs a startup error.

### Security
- `EncryptedStorageService` uses the full 32-byte SHA-256 hash as the AES-256 key and derives an independent salted HMAC key; legacy AES-128 payloads migrate automatically on first decrypt.
