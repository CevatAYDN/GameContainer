### Fixed (Adversarial Audit - 2026)
- **SaveThrottler Lock Discipline + Silent Save-Loss Race (SaveThrottler.cs)** — `Tick()` now claims due slots under `_lock` and flushes user save actions OUTSIDE it: holding the lock across `action.Invoke()` serialized every save behind the slowest action and risked deadlock when an action blocked on a thread that wanted `_lock`. `FlushSlot` also queues a request that races an in-flight flush as pending instead of silently dropping it, so the newest state is never lost.
- **GameSaveManager Non-Async Lambda + Documented Backoff (GameSaveManager.cs)** — removed a pointless `async` on the `Task.Run` lambda (CS1998) and documented why the retry backoff stays inside the serialized stage+rename critical section (releasing `_saveLock` between attempts could clobber a concurrent same-slot save).
- **NEXUS003 Sync-Over-Async Detection (NexusArchitectureAnalyzer.cs)** — the analyzer now also flags `GetAwaiter().GetResult()` (not just `Thread.Sleep`) and honors a trailing `// NEXUS003-exempt: <reason>` marker for deliberate, documented sync sites (EncryptedStorageService 1-2 ms IO backoff, NexusTestHarness rethrow-only GetResult). Rule locked by new editor tests (`NexusArchitectureAnalyzerTests`).
- **Editor FPS Monitor Reading Editor-Context Time.deltaTime (PerformanceDashboardPlugin.cs)** — the dashboard computed FPS as `1f / Time.deltaTime` inside the editor window's scheduled callback. The FPS alarm/label-color logic is also guarded (`fps > 0f`) so a not-yet-sampled metric (0.0) no longer paints the old bogus red alarm. In editor context `Time.deltaTime` is the time since the last RENDERED game frame, which balloons whenever the Game view is occluded by the Dashboard or the editor is busy repainting — showing bogus 1-4 FPS (and firing the "FPS below threshold" alarm) even when the game runs at 60. The dashboard now reads the game-recorded `PerformanceMonitor.GetMetric("FPS")` (sampled by `MetricsSampler` in the real Update loop), so the monitor reflects actual game FPS.
- **ResourcesUIAssetProvider Poll Loop (ResourcesUIAssetProvider.cs)** — `InstantiateWindowAsync` polled `Resources.LoadAsync` with `while(!request.isDone) { await Task.Yield(); }`, re-scheduling a continuation every frame and delaying the first window open after Play by many frames. It now bridges `AsyncOperation.completed` (2020.1+) through a `TaskCompletionSource`, so the await resumes the moment the load finishes instead of polling every frame. (Unity's `AsyncOperation`/`ResourceRequest` is not natively awaitable — no `GetAwaiter` — so a direct `await request` would not compile; the TCS bridge matches the existing `GameSaveManager`/`WindowManager` pattern.)
- **Starter Scene Missing QueueDrainer + MetricsSampler (NexusStarter.unity)** — the `GameRoot` GameObject carried only `Root` + `GameLifecycle`. Without `QueueDrainer`, the context's `HybridQueue` was NEVER drained in the demo (queued signals/commands silently never ran); without `MetricsSampler`, the game never recorded FPS/memory/GC metrics, so the Performance Dashboard (which reads `PerformanceMonitor.GetMetric("FPS")`) would read a flat 0.0. Both components are now added to `GameRoot`.
- **Reentrancy Counter Drift (SignalBus.cs)** — Fixed `s_stackDepth` and `s_asyncStackDepth` counter drift when reentrancy limit exceeded. Now uses `enteredDepth` flag to ensure counter is only decremented if increment succeeded, preventing negative drift across nested dispatches.
- **Cross-Thread Singleton Construction Race (NexusDI.cs)** — Replaced spin-wait with `ManualResetEventSlim` for proper thread synchronization during concurrent singleton construction. Eliminates 10s timeout waste and ensures atomic publication.
- **Unsubscribe-Dispatch TOCTOU (SubscriptionRegistry.cs)** — `SubscriptionNode.Reset()` no longer clears `Next` pointer, allowing in-flight dispatch iterations to safely traverse the linked list even when nodes are pooled during sweep.
- **Original Exception Preservation (RecoveryEngine.cs)** — Strategy failures now collect BOTH the strategy exception AND the original command exception in `ErrorCollection`, preventing loss of root cause during recovery.
- **PostContext Builder Reference (Context.cs)** — Added `_configuredBuilder` field to track the exact builder used during `Configure()`, ensuring `OnPostContext` receives the correct builder with all reactive model/service type lists.
- **Metrics Rate Race (NexusRuntime.cs)** — `_lastSampleTime` read moved inside `_rateLock` for atomicity on ARM weak memory ordering.
- **Logger Cache Invalidation Race (NexusRuntime.cs)** — Replaced `Volatile.Read/Write` with lock-based cache for thread-safe logger access during context register/unregister.
- **Decorator Closure Allocation (CommandExecutor.cs)** — Restored the non-allocating dispatch call for the generic sync path AND eliminated the same closure class in the async/object paths: an inline lambda capturing `signal`/`command` (both referenced from catch/finally) made Roslyn hoist a closure display-class to method entry (~56 B per dispatch on the sync path, caught by the zero-GC harness and confirmed via IL dump). The async sync-command branch and the object-path generic-only dispatcher branches now gate on decorators and route through `[NoInlining]` helpers (`ExecuteDecoratedCommand`/`ExecuteDecoratedDispatcher`/`ExecuteDecoratedAsyncDispatcher`). Measured on the x64 reference harness: `FireAsync` + sync-command dropped by ~120 B/dispatch after the fix. Decorator chains are composed on demand and only entered when decorators are registered.
- **Async Depth Guard Boxing (SignalBus.cs)** — the async reentrancy guard stored depth in `AsyncLocal<int>`, boxing a fresh int on every entry AND exit (~192 B/op standalone; ~96 B/dispatch on `FireAsync`). Depth now lives in a mutable boxed holder (`AsyncLocal<AsyncStackDepthBox>`): entry get-or-creates the box once per root flow, the exit decrement is a plain field write (zero AsyncLocal traffic), and nested dispatches inherit the box reference (nothing to allocate). The box is shared by every flow derived from one root execution context — exactly the tree-depth semantics a runaway-chain guard needs — while independent roots (separate `FireAsync` calls from sync code) still get isolated boxes. Measured on the x64 harness: `FireAsync` + sync-command dropped 288 → 192 B/dispatch (the diagnostics primitive shows `AsyncLocal<int>` 192 B/op vs `AsyncLocal<boxed>` 0 B/op).
- **LazyInjection Thread-Safety (NexusDI.cs)** — Double-checked locking in `InjectFields`/`InjectProperties` ensures only one `LazyInjection` instance is created per field/property under concurrent injection.
- **Composite Payload Capture (SignalBus.cs)** — Each composite trigger now receives its own boxed signal instance, eliminating shared reference risk.
- **Fallback Command Depth Guard (RecoveryEngine.cs)** — Added `_fallbackDepth` counter with `MaxFallbackDepth = 3` and negative priority (-1) for fallbacks, preventing infinite fallback loops and ensuring proper execution order.
- **One-Shot Claim Atomicity (CommandRegistry.cs)** — `TryClaimOneShot` now marks handler as claimed but keeps in list until execution completes, preventing lost retries.
- **HybridQueue Drain Error Visibility (HybridQueue.cs)** — Drain failures are logged via `NexusRuntime.Logger` and draining continues; a failing queued signal is still released and counted, so one bad signal cannot stall the rest of the queue.
- **Trace Buffer Resize Race (NexusRuntime.cs)** — `ApplyTraceBufferSize` now uses versioned buffer swap with `Volatile.Read/Write` for lock-free reader safety.
- **Benchmark harness SecureData cleanup (tools/nexus-benchmark)** — `FullArchitectureStressSuite` now only attempts the `SecureData` folder deletion when the folder exists, eliminating the spurious `DirectoryNotFoundException` "cleanup failed" log on every run.
- **SaveThrottler Tick zero-allocation (SaveThrottler.cs)** — `Tick` no longer allocates a `List<SaveSlot>` + `ToArray()` on the due path (NEXUS001 hot-path allocation). Due slots are collected into a reusable `[ThreadStatic]` buffer, with a depth guard renting a fresh list only for a (pathological) re-entrant `Tick` on the same thread — mirrors the `ObjectPoolService` callback-depth convention. Steady-state `Tick` is now allocation-free.
- **Code Health Analyzer precision (NexusArchitectureAnalyzer.cs)** — `NEXUS004` now skips `#pragma warning disable CS0618` regions (the sanctioned backward-compat pattern: demo screens, `CasualServicesPlugin` legacy panel), trailing comments, and string literals, so it flags genuine NEW `WindowManager` references only — the 14 reported findings on comments, localization strings, and pragma-guarded bindings no longer fire. `NEXUS001` applies the same comment/string stripping. Both rules are locked by new editor tests (`NexusArchitectureAnalyzerTests`). *(Superseded this release — `NEXUS004` is retired together with `WindowManager`; see Removed.)*

### Changed
- **Decorator Chain Caching + Closure-Free Runner (CommandExecutor.cs)** — flattened decorator chains are now cached per plugins-snapshot reference and re-validated per-plugin decorator snapshot references on every lookup, so runtime `RegisterCommandDecorator` calls (including inside `OnPluginRegistered`, which runs after the context's snapshot rebuild) invalidate the chain with no explicit invalidation protocol. The per-dispatch List build + plugin iteration + AddRange are gone. On the decorated SYNC path, a pooled, ThreadStatic `DecoratorRunner` walks the cached chain with a single pre-created delegate — per-level closure allocations eliminated (re-entrancy-safe: nested dispatches rent a fresh runner; the only remaining per-dispatch allocation is the caller's tail closure, which must capture the pooled command instance). ASYNC chains compose from the cached chain but keep per-level async lambdas (their state must survive awaits, so the pooled runner cannot be used) — documented tradeoff. New harness test `8b. DecoratorChain_Order_And_CacheInvalidation` locks in the outermost-first execution order (`B2→B1→A2→A1` for plugins A(A1,A2), B(B1,B2)) and proves a late-registered decorator appears on the very next dispatch.

- **Logger Cache Locking** — `NexusRuntime.Logger` uses lock-based cache for thread-safe access during context lifecycle changes.
- **LazyInjection Double-Check** — `InjectFields`/`InjectProperties` use double-checked locking for thread-safe lazy instance creation.

### Fixed
- **`BigDouble` value-equality contract (B1/B2/Or3)** — `Equals` previously compared mantissas with a `1e-12` tolerance while `GetHashCode` used the raw `Mantissa` and `CompareTo` used the `double` default comparison, so equal values could hash differently and an `Equals`-positive pair could `CompareTo != 0` (breaking `SortedSet`/`Dictionary`/sorting invariants). `Equals` is now exact (`Exponent == other.Exponent && Mantissa == other.Mantissa`), `GetHashCode` stays `HashCode.Combine(Mantissa, Exponent)` (now consistent), and `CompareTo` gained early zero/sign branches plus exact `Mantissa.CompareTo`. `operator *` / `operator /` also saturate exponent arithmetic (`SaturateAddExponent`/`SaturateSubExponent`) so a huge product no longer overflows the `long` exponent and silently corrupts the value.
- **`GameSaveManager` main-thread context capture (İ2)** — `_mainThreadContext` was captured in a field initializer (`= SynchronizationContext.Current`) at *type-load* time, when `SynchronizationContext.Current` is still null, so `LoadAsync` could never re-enter the Unity main thread. It is now a lazy `MainThreadContext => _mainThreadContext ??= SynchronizationContext.Current` accessed at first `LoadAsync` call (guaranteed on the main thread), fixing the dead capture.
- **`NexusDI.Dispose()` fire-and-forget ordering (İ3)** — async singletons were disposed one fire-and-forget task per instance (`_ = instance.DisposeAsync()`) launched in parallel with no ordering, so registration-dependency order was lost and continuations could re-capture the disposing thread's `SynchronizationContext`. `Dispose()` now collects `IAsyncDisposable` instances and runs them through a single ordered thread-pool chain `DisposeAllAsyncInBackground` (sequential `await ...ConfigureAwait(false)` per item with per-item error capture); the deterministic `DisposeAsync()` path remains for callers that can await.
- **`ContextLifecycleOrchestrator` await re-capture (İ3)** — `StopAsyncInternal` now `await ...ConfigureAwait(false)` so the stop continuation stays on the thread pool instead of hopping back to the caller's context.
- **Recovery abort exception identity (İ4)** — the recovery engine's Abort / retry-limit throws were plain `InvalidOperationException` and the strategy-failure `catch` filtered on `InnerException == ex` object identity, which misfires when a strategy legitimately wraps the original error. A typed `NexusRecoveryAbortException : InvalidOperationException` (preserving the existing catch/assert contract) is thrown by both paths and the filter now matches on type (`when (!(strategyEx is NexusRecoveryAbortException))`).
- **`GameStateMachine` cancellation terminal state (Or1)** — a bare `catch (OperationCanceledException)` in the error-state recovery path left `_currentState` stale after a cancelled recovery. It now reaches the same terminal `null` state (guarded by the transition sequence) as the inner-exception path, preventing a stale "failed-from" state leak.
- **Anti-Cheat Integrity Canary (`SecureObservableProperty.cs`)**: Fixed dead-code branch in tamper detection so canary failures log security warnings and reset tampered values to defaults.
- **Encrypted Storage Seed Exception Logging (`EncryptedStorageService.cs`)**: Replaced bare `catch` in seed decoding with explicit `catch (Exception ex)` and warning log before fallback seed regeneration.
- **Command Injection Performance (`CommandRegistry.cs`)**: Optimized signal injection setters using compiled `System.Linq.Expressions` to eliminate `FieldInfo.SetValue` reflection overhead in hot paths.
- **Service Dependency Property Injection (`NexusService.cs`)**: Changed `Context` and `SignalBus` property setters from `private set` to `protected set` for property injection compatibility.
- **Domain Lifecycles Execution (`ContextLifecycleOrchestrator.cs`)**: Enabled dual execution of `IAsyncStartable` and `IStartable` (and stoppable equivalents) when a domain object implements both contracts.

### Security
- **DI validation runs in ALL build targets (A10)** — the Configure-time `ContextBuilder.Validate()` call was previously compiled out under `UNITY_EDITOR`, so production builds silently skipped every check (missing dependencies, constructor explosion, and the A8 captive-dependency rule) and left `[Inject]` fields null with no diagnostic. Validation now runs in every build, is logged (never throws), and can be disabled for projects that intentionally defer bindings past Configure via the new `ContextBuilder.ValidateOnStartup` flag (default `true`).
- **ErrorCollection grouping counters bounded (A10)** — `s_errorGrouping` (unique `category:message` → count) previously grew without bound even though the error bag is capped at `s_maxErrors`, so long sessions with dynamic error messages (URLs, ids, filenames) leaked memory. When unique keys exceed 4096 the counters are rebuilt from the retained bag; `Count` now reflects occurrences among retained entries rather than cumulative-ever.
- **Async in-flight overflow throws in ALL builds (A9)** — `CommandExecutor`'s `MaxInFlightAsyncCommands` guard previously logged and silently dropped the command in Release while the caller's async chain completed "successfully"; it now throws `NexusAsyncOverflowException` unconditionally (same principle as the A8 reentrancy guard), and the guard is unified into a single `EnterAsyncInFlight()` used by all four async dispatch paths — including composite async commands, which previously bypassed the cap entirely.
- **NetworkMonitor latency history is thread-safe (A9)** — `s_latencyHistory` and the shared `ConnectionStatus` were written from network/background threads and read from the game/editor thread on a plain `Dictionary` (the same BUG-17 race `PerformanceMonitor` already fixed). All access is now guarded by a dedicated `s_historyLock`.
- **Reentrancy guard throws in ALL builds (A8)** — `SignalBus` no longer silently returns on `MaxStackDepth` overflow in Release/development-less builds; the `#if UNITY_EDITOR || DEVELOPMENT_BUILD` guard was removed from both the sync and async dispatch paths, so a runaway signal chain now always throws `NexusReentrancyException` (skill checklist §7) instead of hiding state corruption.
- **Atomic save writes everywhere (A8)** — `GameSaveManager` now publishes saves with a single overwrite-rename (`File.Replace`, fallback `File.Move`) instead of the delete-then-move pair that left a crash window where the only good save was already deleted (skill checklist §4.1).
- **Non-blocking teardown (A8)** — `Context` now implements `IAsyncDisposable` (`DisposeAsync()`); the synchronous `Dispose()` path no longer blocks the Unity main thread on `IAsyncDisposable` singletons — async disposal is scheduled on the thread pool with error capture (skill checklist §3.1). Callers that can await should prefer `await context.DisposeAsync()`.
- **Hardware-tick offline anti-cheat (A8)** — `OfflineTimeCalculator` now stores a hardware monotonic tick (`Stopwatch.GetTimestamp() * 1000 / Stopwatch.Frequency`, ms since boot) alongside the wall clock and clamps offline rewards to the hardware-measured elapsed time, closing the forward-clock hole (skill checklist §4.1). On reboot (monotonic reset) it falls back to wall-clock-only validation, still capped.
- **Captive-dependency validation (A8)** — `ContextBuilder.Validate()` now reports `DiValidationIssueType.CaptiveDependency` when a singleton service captures a transient (non-singleton, non-factory) dependency in its constructor or `[Inject]` members (skill checklist §2.2).

### Changed
- **NetworkMonitor `CurrentStatus` returns a defensive snapshot (A9)** — the property previously exposed the live shared `ConnectionStatus` instance (readers could observe — or mutate — concurrent updates); it now returns a copy built under the lock, and `OnConnectionStatusChanged` delivers a snapshot too. This is a deliberate contract change: consumers must not hold the reference expecting live updates. Snapshot construction lives in one `SnapshotStatus()` helper.
- **ObjectPoolService — dropped obsolete API (A8)** — the `GetInstanceID()` reflection hack and the `#pragma warning disable 0619` suppressions were removed in favor of the Unity 6 `Object.GetEntityId()` API (skill checklist §5.1 zero-warning policy); also fixed a `CS0649` in `NexusBinding._customTargets`.
- **AssemblyCatalog (editor) — one deep module owns "which assemblies do tools scan?"** — the `GetLoadedAssemblies() → filter → GetTypes()` loop was previously re-implemented ~24× across 11 editor files (NexusWindow, BuildValidation ×10, NexusEditorDataProvider, NexusCodeGenerator ×2, Dashboard/Explorer/GameManager/Graph/TypeAnalyzer/Wizard plugins) with **four divergent filter predicates**, so tools disagreed about what code they could see. New `Editor/Core/AssemblyCatalog.cs` centralises iteration, the predicates (framework / third-party / test / editor classification) and the safe `GetTypesSafe` enumeration (a `ReflectionTypeLoadException` yields the partially-loaded types + one warning instead of throwing). All 11 call sites route through it. **Behavior notes:** test assemblies and third-party assemblies (Newtonsoft, Grpc, ExCSS, log4net, TextMateSharp, Onigwrap, Plastic/Codice, MCPForUnity, JetBrains) are now *consistently* excluded from every scan — previously only BuildValidation excluded them, so dashboard/GameManager type counts and Explorer/TypeAnalyzer search reach shrink slightly; `UnityEditor.*` assemblies are also excluded from NexusWindow plugin discovery (plugins never lived there).
- **NexusFieldInspector (editor) — one module owns the type→UI Toolkit field mapping** — the near-identical switch trees in `ExplorerPlugin.CreateSignalFieldUI` and `HierarchyPlugin.CreateFieldUI` (which had already drifted: read-only support, undo hooks, fallback labels) are replaced by `Editor/Core/NexusFieldInspector.cs` (`CreateField` + `EnumerateMembers`). Hierarchy keeps its undo hook and live binding-tracker wiring via callbacks; Explorer keeps its localized unsupported-type fallback.
- **RecoveryEngine — one decision tree, two thin entry points** — the ~70-line failure-decision policy previously duplicated in `HandleErrorWithDecision` / `HandleErrorWithDecisionAsync` is now a single `BuildPlan` with thin sync/async wrappers, so retry/recovery semantics cannot drift between the two paths.
- **Test harness routes through production registration** — `SignalBus.RegisterCommandType` is now the shared registration path for both the runtime assembly scan (`Context`) and the test harness (`NexusTestContext`), so attribute parsing and sync/async classification can never drift between production and tests. `NexusTestContext` now exposes the production `IContextBuilder` (instead of re-declaring a parallel `Bind` surface) and no longer pre-binds command types (the registry binds them itself).
- **DashboardSections** — removed `DashboardPlugin.CreateSectionTitle`, a shallow passthrough to `DashboardSections.CreateSectionTitle`; call sites now call the module directly.

### Security
- **SecureObservableInt/Long/Float/String** — memory obfuscation upgraded from single-XOR to **dual independent keys** with integrity canary (`_guard`). (Previously: single key stored adjacent to value — GameGuardian/CheatEngine read both fields.)

### Security
- Added `SecureObservableLong` (XOR-masked RAM obfuscation, mirroring `SecureObservableInt`) and migrated `EconomyService` balances to it — currency values are no longer stored as plain `long` in memory, closing the anti-cheat gap flagged for RAM scanners (GameGuardian/CheatEngine).

- `IapService` editor/dev mock ownership is now guarded by a **salted, rotating-mask checksum** over `_mockOwnedProducts` — a RAM scan (GameGuardian/CheatEngine) can append a fake product ID to the HashSet, but `IsProductOwned` recomputes the checksum before every read, detects the mismatch, wipes the tampered set and denies the forged ownership (fail-closed). Hardening beyond the original session-stable hash: the checksum is folded with a per-instance salt (`_mockOwnedSalt`) and XOR-masked by `_mockOwnedMask` which rotates (`*31+17`) on every successful verify — so value-scans fail across instances and snapshot-replay of an observed (checksum, mask) pair is detected on the next read. Still deterrence, not a security boundary: the real ownership gate is the release `#else` path that never trusts the mock set.
