# Changelog

All notable changes to the Nexus Core package will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This is the changelog of the core and its adapter packages (`com.nexus.iap.unity`, `com.nexus.firebase`,
and the history of `com.nexus.ads.admob`'s legacy `AdMobAdapter` until issue #14 removed it); the ad package
family has its own, `com.nexus.ads/CHANGELOG.md`. The package version in `package.json` is the released version;
everything under Unreleased is in the repository but not yet in a tagged package.

## [Unreleased]

### Added
- **Firebase in one binding call, collection off in the manifest** (`com.nexus.firebase`, issue #78): `FirebaseBindings.Bind<TConsent>(builder)` binds `IAnalyticsService`, `IRemoteConfigService` and `ICrashReporter`, the Firebase service of each installed SDK in a player and the mock in the Editor and without the SDK, and the game's consent reader only where a Firebase service reads it (otherwise a `NotRequired` mock consent). The SDK defines exist only inside the package, so Wickling kept its own define and ChipCrisis bound nothing. `FirebaseCollectionFlags` (new Editor assembly `com.nexus.firebase.editor`) writes `firebase_analytics_collection_enabled` and `firebase_crashlytics_collection_enabled` as `false` into the launcher manifest on every Android build for each installed SDK, keeping a flag the game set; the services turn collection on after consent. EditMode `FirebaseBindingsTests` (3).
- **Pause holds for screens and ads that open over each other** (issue #77): `ITickService.HoldPause()` returns a handle; ticking stays paused while any handle is held or the `IsPaused` flag is set, and resumes when the last handle is disposed (disposing twice is harmless). One `IsPaused = false` from a closing ad no longer resumes a shop that is still open; games kept their own counted pause service for this. PlayMode `TickServiceTests.TickingResumesOnlyWhenEveryPauseHoldIsReleased`.
- **A testing kit a game can reach** (issue #74): `com.nexus.core.testing` compiled only where `UNITY_INCLUDE_TESTS` was defined, which a package not listed in `testables` never gets, so a game's test assembly that referenced it failed with CS0234 (`NexusTestHarness` not found; ChipCrisis re-implemented the harness and the allocation probe, Gigawatt copied core test files). The assembly now compiles in the editor and for test players (`UNITY_EDITOR || UNITY_INCLUDE_TESTS`); a release player of the development project still holds no `com.nexus.core.testing.dll`. New in it: `RecordingSignalBus` (records every fired signal, calls the test's subscribers, refuses async subscribers on `Fire` as the real bus does) and `InMemoryPlayerPrefsService` (stores as `UnityPlayerPrefsService` does, so a read under another type answers as on a device; counts `Save`). `MockAdNetworkAdapter.RewardOutcome` selects Rewarded, Closed, Failed or NotReady. EditMode `TestingKitTests` (the bus; every cross-type read against `UnityPlayerPrefsService`; the mock outcome); the clean consumer gate now writes no `testables` unless `-ValidatePerformance` asks for the package's suites, and its project's own test assembly uses the kit: `consumer-20261027-kit` passed, where `consumer-20261027-kit-red` on the previous constraint failed with CS0234.
- **Awaitable rewarded ads and purchases** (issue #73): `IAdService.RequestRewardAsync(placement, ct)` and `IIapService.PurchaseAsync(productId, ct)` (extension methods, `MonetizationAsyncExtensions`) complete with the `AdOutcome` / `PurchaseOutcome` of `RequestReward` / `Purchase`, so an `IAsyncCommand` awaits the answer; with the callbacks, a pooled command had returned and its `[Inject]` members were cleared before the answer arrived (Wickling's `ClaimRewardCommand` captured locals for this). The continuation never runs inside the SDK's callback. Cancelling stops the wait, not the ad or the store; a reward or purchase that completes afterwards logs a warning. Every adapter answers through the services, the ad family's bridge included. EditMode `MonetizationAsyncTests` (an async command grants after a reward that arrives later; a cancelled wait and the late reward's warning; a purchase the store reports later), `NexusAdsBridgeContractTests.RequestRewardAsync_AwaitsTheBridgesOutcome`.
- **Context started, pause and resume signals** (issue #70): a context fires `ContextStartedSignal(ScopeTag)` when its start-up has run (services, every `OnStartAsync`, the startables, the lazy services resolved during start), just before `IsInitialized` turns true, and `Root` forwards `OnApplicationPause` as `ApplicationPauseSignal(IsPaused)` once its context has started; a pause Android reports before the start is dropped. Wickling fired its own `AppStartedSignal` from `OnStartAsync` and guarded its own pause signals for this. Each is fired only when the bus has a subscriber or command for it, so a game that does not listen gets no "no subscribers" warning. The pause signal is fired synchronously (Android may freeze the process when the call returns): subscribe with `Subscribe`. PlayMode `ContextSignalsTests` (fired once after the services and `OnStartAsync`; a pause before the start not forwarded, a resume after it forwarded).
- **Audio, haptics, economy and progression state where the game keeps it; separate mutes; haptic effects** (issue #71): a bound `SettingsStores` gives each of the four services the `IPlayerPrefsService` it reads and writes (a slot left null uses the bound one; key names unchanged), so a game that keeps economy and progression in its own save, or its settings in its own model, no longer works around the fixed `NT_*` keys. `IAudioService.IsMusicMuted` / `IsSfxMuted` mute the music and the effects separately (persisted; `IsMuted` still mutes both). `IHapticService.CreateEffect(ms, amplitude)`, `CreateWaveform(timings, amplitudes)` and `Play(effect)`: every effect, the six presets included, is built once, and on Android 8+ a trigger goes through a cached JNI method with a prebuilt `VibrationEffect` (the old path allocated a JNI argument array per call); `IsEnabled` now persists (`NT_HapticsDisabled` was read but never written). `IAudioRootProvider.ReleaseRoot(root)` (default: keep it) replaces the check for `DefaultAudioRootProvider`'s type, so a custom provider decides what happens to its root, and the root the service creates when no provider supplies one is destroyed on dispose instead of leaking. `IAudioService` and `IHapticService` gain members: another implementation must add them. The new `[OptionalInject] SettingsStores` members reach a player built with the AOT binder only after the binder is regenerated (**Nexus > Generate AOT Binder**). EditMode tests in `AudioAndHapticServiceTests` (the game's store for audio, haptics, economy and progression; separate mutes; a provider's root handed back; effect validation), PlayMode `AudioServiceRootTests`, harness G5 (`Play` ×2000, 0 B). The Android branch was compiled by an Android IL2CPP player build only (see #71); haptics were not tried on a phone.
- **Localization a game can use without its own wrapper** (issue #72): `JsonLocalizationTableProvider` reads one flat `{"key": "text"}` JSON per language (from strings, or `FromResources(folder, languages)`); a bound `LocalizationOptions` makes the first run pick the device language when the game ships a table for it (`pt` finds `pt-BR`; the built-in `en`/`tr` button texts do not count as a table), else `DefaultLanguage`, without saving the pick; `ILocalizationService.Culture` is the current language's culture (`LocalizationOptions.Cultures` overrides it) and `Format(key, args)` formats a table text with it before the RTL reversal. ChipCrisis, Wickling and Gigawatt kept their own table provider, culture and device-language probe of `NT_Language` for this. `ILocalizationService` gains `Culture` and `Format`: another implementation of the interface must add them. Without `LocalizationOptions` the first run is English, as before. PlayMode tests in `LocalizationServiceTests` (first run, saved language, JSON escapes, culture, the game's culture, RTL formatting). The compile check references the editor's `System.Text.Json`.
- **Package `com.nexus.ads` 0.1.0, Phase 1 of the ads package family** (#8, #9): the policy compliance register `docs/POLICY_COMPLIANCE.md` (+ `_TR.md`), which maps every platform's official policy pages (read 2026-10-24) to a `PolicyGuard` rule id, a validator check or a developer checklist item and records Google's Families self-certified status per network, and the setup wizard's data file `Editor/PlatformCatalog.json` (registration and documentation links, Google's sample ids with their source, the UPM package names, registries and defines of the LevelPlay, MAX and AdMob SDKs, setup steps in English and Turkish). No runtime code. The family's own `CHANGELOG.md` arrives with Phase 2 (#10), when the single-changelog rule moves.
- **Package `com.nexus.firebase` 0.1.0** (Firebase Analytics, Remote Config and Crashlytics behind Nexus services, with their rules and mocks): the Firebase name and value limits for events, parameters and user properties (`AnalyticsEventName`, `AnalyticsUserProperty`, `AnalyticsParameterValue`); the consent decision with the player's choice read through `IAnalyticsConsent`, and a gate that holds events until the answer is known and drops them when analytics are refused (`AnalyticsCollectionPolicy`, `AnalyticsGate`); `IRemoteConfigService` with typed reads that fall back to the game's default, a 12-hour fetch cache (`RemoteConfigFetchPolicy`) and an invariant-culture parser (`RemoteConfigParser`); `ICrashReporter`; mocks for the editor, development builds and tests; and the SDK adapters `FirebaseAnalyticsService`, `FirebaseRemoteConfigService` and `FirebaseCrashReporter`, which compile only while their Firebase package is installed (`versionDefines`, defines `NEXUS_FIREBASE_ANALYTICS` / `NEXUS_FIREBASE_REMOTE_CONFIG` / `NEXUS_FIREBASE_CRASHLYTICS`). Verified by EditMode tests with no SDK, and by compiling the adapters against Firebase Unity SDK 14.0.0 in a disposable project; the adapters have not been run on a device. Install notes and the platform-manifest caveat for consent are in the package README.
- **Adapter packages** `com.nexus.ads.admob` 0.1.0 (Google AdMob through the Google Mobile Ads Unity plugin, with User Messaging Platform consent: rewarded, interstitial, banner, `AdOutcome`, `ReadyChanged`, privacy options) and `com.nexus.iap.unity` 0.1.0 (Unity IAP 5: catalog, `PurchaseOutcome`, restore, ownership, localized prices, `StoreChanged`). Each compiles only while its SDK package is installed (`versionDefines`, defines `NEXUS_ADMOB` / `NEXUS_UNITY_IAP`); ported from the first shipped Nexus game; verified by compiling against the real SDKs in a disposable project and by before-initialization tests (`docs/ADAPTERS.md`, "Shipped adapters").

### Fixed
- **A Nexus package update no longer breaks a game's generated binder** (issue #110). The binder and `link.xml` a game generates named the packages' own types: 20 of Gigawatt's 161 registered types, 31 of Wickling's 91, 28 of ChipCrisis's 119. A type that a package removed therefore broke every game's binder compile (`FloatingTextService` #91, `AdMobAdapter` #14).
  - **What changed.** Both generators now leave out the packages' assemblies: **Nexus > Generate AOT Binder** and the Roslyn source generator. The rule is `NexusAssemblyPolicy.IsNexusPackageAssembly` (`com.nexus.*`, `Nexus.Ads.*`). Those types take the reflection path.
  - **Preservation.** Each package preserves its own types in its own `link.xml`:
    - `com.nexus.core`: the `Nexus.Core.Services` namespace, and `com.nexus.core.dots`;
    - `com.nexus.firebase`, `com.nexus.iap.unity`, `Nexus.Ads.Bridge.Nexus` and `Nexus.Ads.AdMob.Firebase`: the whole assembly, with `ignoreIfMissing`.
  - **The linker reads them.** Unity 6000.5.6f1 passes UnityLinker only the `link.xml` files under `Assets`. No package's file was read before: neither core's `Runtime/link.xml`, older than this change, nor the files the first #110 commit (`95e4c30`) added. The editor class `NexusPackagesLinkXml`, an `IUnityLinkerProcessor` like the Input System's, merges the `com.nexus.*` packages' files into `Library/Nexus/PackagesLink.xml` and hands that to the linker. A file that does not parse is left out with a warning.
  - **Proof at High stripping.** On the development Android IL2CPP player built without the processor, the linker removed `com.nexus.firebase`, `com.nexus.iap.unity` and `Nexus.Ads.Bridge.Nexus` whole, despite `preserve="all"`. With the processor all five package assemblies are in `ManagedStripped`. On the phone the player's probe constructs `AdService`, `IapService`, `LocalizationService` and `HapticService` in a fresh context and reads back their injected members: 4 of 4 (`NexusVerifyBuild.BuildAndroidIL2CPPDevelopmentHighStripping`, tools/unity-verify). EditMode `PackagesLinkXmlTests` and harness CG7 (every package `link.xml` parses) lock the processor and the files. At High stripping that player's own start-up scene fails for an older reason, which is separate (#113). The projects build at Minimal, where the linker copies the package assemblies whole.
  - **What moves to reflection.** The core services had no constructor factory before either (`fcdfc07`): for them only the generated injector goes. The adapter packages' types lose their generated construction and injection.
  - **What stays generated.** A game type keeps its generated injector for the members it inherits from a framework base class.
  - **Upgrading.** A binder generated before this change still names package types, so the first update past it needs one regeneration (TROUBLESHOOTING, "Stale Generated Binder").
  - **Harness CG6.** A fixture assembly named like a package: neither generator registers, preserves or lists its types. It is red on the previous generators.
  - **Harness CG7.** Every runtime assembly under `Nexus/Packages` must match both generators' rule. When it references the core, its package's `link.xml` must preserve it, with `ignoreIfMissing` when a define gates it. It was red before the package files.
  - **AOT1 moved.** The harness check AOT1 read the development project's binder, which git ignores. It is now a CG1 fixture: `[OptionalInject]` is emitted as `TryResolve`, and an unbound member stays null.
- `NativeSignalQueue<T>`'s summary called it a "thread-safe, lock-free, Job/Burst-compatible queue" (issue #109). Nothing in the repository is Burst-compiled or Burst-tested, and the struct's own `Enqueue` takes one exclusive writer; jobs write through `AsParallelWriter()`. The summary now says that, as the package documents already did.
- The package shipped `Tests/Runtime/TestUtilities.meta`, a folder meta whose folder has had no files since before 0.5.0 (issue #106). Git keeps no empty folders, so a game installing the package by git URL got a meta without its folder. The meta is removed.
- Every build warned that `AdService`, `IapService`, `AnalyticsService` and `FeedbackService` were stubs, whatever the game had connected, and three of the messages named adapters that do not exist (an AdMob / IronSource adapter, RevenueCat, Amplitude) (issue #104). None carries `[StubService]` any more: `AdService` and `IapService` host an adapter and log `No adapter configured ... in a release build` at run time, `FeedbackService` plays through the haptic and audio services, and an `AnalyticsService` that only logs is a state a game may ship (a game with `com.nexus.firebase` binds `FirebaseAnalyticsService`). The attribute and the build check stay for a game's own placeholders; EditMode `StubServiceWarning_NamesOnlyTypesMarkedAsStubs_NotTheFrameworksServices` failed on the old code with five warnings.
- `AdService` raised no `ReadyChanged` when its own interstitial cooldown ended (issue #99): the event only forwarded the adapter's, so without the ad family's bridge (the mock adapter from `AdAdapterFactory`, or a game's own `IAdNetworkAdapter`) a UI that follows the event kept an interstitial button hidden after the cooldown, and only polling noticed. `AdService` is now an `ITickable`: with an `ITickService` in the context (`[OptionalInject]`, as in `InputService`) it registers in `InitializeAsync`, the first tick after the cooldown ends raises the event once, and `Dispose` unregisters it. After a show, `SetInterstitialCooldown` re-arms the check: the event comes on the first tick at which the new cooldown no longer blocks (the next tick, when it already does not). While ticking is paused the event comes on the first tick after the resume; without a tick service nothing changes. With the bridge the event comes when `AdService`'s cooldown ends, before the controller's gap, which raises its own (#95). A binder generated before this change does not inject the new member: the runtime check from #81 injects it by reflection and logs a warning until the binder is regenerated. Harness D4b (no event inside the cooldown, one at its end, none after `Dispose`) and GCA9 (idle, cooling and ending ticks 0 B) fail with the wake disabled.
- The documents did not say what a storage write costs, and `GAME_PATTERNS.md` gave per-frame GC budgets that read as framework guarantees (issue #100): ChipCrisis measured about 25 KB of framework allocation per `EncryptedStorageService` key write on Android IL2CPP against the Idle pattern's "< 500B GC/frame". The Performance scope table has a storage row (what a write creates, the measurement, the game chooses how often it saves), the Economy row says GCA8's save action is a counter, and the budgets are marked as the game's targets for steady-state frames. The framework does not cut the write's own allocations (#100, closed as not planned): frame time was unaffected and a save frame is outside the per-frame budgets; it reopens when a game's capture shows a save dropping a frame.
- The package's allocation claims went further than its proofs (issue #97): comments and documents called 76 places "0-GC" or "allocation-free", while the README's **Performance scope** table, where the contracts live, had 6 rows and said the harness and `PerformanceTests` assert them (the typed composite's proof is the EditMode `TypedComposite_SteadyStateHasNoManagedAllocation`, and warmed DI resolution has a comparison measurement, no regression check). One claim was false: `SubscriptionRegistry` said `Subscribe` and `Unsubscribe` allocate nothing, while a `Subscribe` allocates its subscription and a new read copy and the sweep after `Unsubscribe` a new read copy; only the node is pooled. The table now has a row per proven path (dispatch, command pools, DI resolution, the typed composite, observables, `TickService`, `HybridQueue`, the netcode history, input, audio and localization, binder and subscription reads), each naming its check, and says which checks fail on any byte and which allow 128 B per loop. Two per-frame paths a game runs got their proof first: a subscribed economy balance (ChipCrisis's HUD) and `SaveThrottler.Tick` (harness GCA7, GCA8, 0 B). Every other line now names its check or the table, or describes the mechanism without the claim; the `_TR.md` translations changed with their sources.
- `InputService` could miss the first Android back press after a cold start (issue #92): `GetButtonDown("Cancel")` read `Keyboard.current.escapeKey.wasPressedThisFrame`, and on Android the keyboard appears with the first key event, so that read's first call came in the update that already held the press. A first call only compares this frame with the last; the back key's press and release can land in one update, the key read as released, and the press was lost (with Predictive Back Support on, Android does nothing either). On the test phone (2311DRK48G, Android 16, ChipCrisis on f928328, `adb shell input keyevent KEYCODE_BACK` 14 s after a cold start) 5 of 11 first presses were lost, none after a Shift key had created the keyboard, none of the second presses. The built-in buttons ("Cancel"/"Pause" on Escape, "Jump"/"Submit" on Space and Enter) are now `InputAction`s the service creates and enables in `InitializeAsync` and disposes in `OnDispose`: an action records every event and binds a keyboard added later. Same keys and contract; a service built by hand reports these buttons after `InitializeAsync`, as its movement already needed. PlayMode `InputServiceButtonTests` (a keyboard added after the service, press and release in one update) failed with (False, False) before and passes now. The phone run on a game built against this fix is still to be done.
- The first `HapticService.Play` of a process allocated once on Android IL2CPP (issue #84): IL2CPP creates a method's string literals on its first call, and the play method held the two literals of its failure and Android 7 branches. They moved to their own methods, so the play method's first-call block resolves method metadata only (read in the generated C++). On the test phone (2311DRK48G, Android 16, Unity 6000.5.6f1 IL2CPP development player, `DeviceProbe`) the first play logged 1 `GC.Alloc` sample before and 0 after; the first play of a second effect and 10 later plays logged 0 both times. The issue's reading (the first play of each effect allocates) did not reproduce; Wickling's 86 B sample after an earlier play is still to be measured again in the game.
- `OfflineTimeCalculator` clamped a phone's time away to its awake minutes on Android (issue #77): its tamper bound read `Stopwatch`, which on Android is `CLOCK_MONOTONIC` and stops in deep sleep (the test phone, 2311DRK48G, logged 3 h 11 min of screen-off time with 29 min awake in `batterystats`), so a pocketed phone earned less offline progress than the wall clock allowed. On Android players it reads `SystemClock.elapsedRealtime`, which counts deep sleep; elsewhere it keeps `Stopwatch` (iOS's sleeping clock and a reboot with more uptime than before the quit are marked `shortcut:` in the code). On the phone (`DeviceProbe` in the Android IL2CPP development player, `NexusVerifyBuild.BuildAndroidIL2CPPDevelopment`) it gave the right time away for 12 s in the background and 245 s with the screen off with the USB cable in (no deep sleep), and 1019 s for 17 min with the screen off and the cable out, while `Stopwatch` counted 51.5 s of them.
- TROUBLESHOOTING told a headless pipeline to empty a stale binder by hand before `GenerateBinder` (issue #77): with `-ignorecompilererrors` the Editor self-heal runs in batchmode and one command writes the binder from the current code (checked on 6000.5.6f1 with a binder naming a deleted type: plain run exit 1 with CS0234, flagged run exit 0 and a binder equal to a clean one). The page gives the command and its caveat (the flag lets other compile errors through, so the build or tests run next).
- A release player ran `PerformanceMonitor` and `NetworkMonitor` (issue #77): the first context turned both on in every build, so a shipped game recorded frame and network samples nobody read, and games set `Enabled = false` themselves. They now start on only in the Editor and development builds (`DefaultEnabled`); a release player records nothing until the game sets `Enabled = true`, and a value the game set before the first context still wins. `ErrorCollection` stays on everywhere. Harness `ReleasePlayer_MonitorsStayOffUntilTheGameTurnsThemOn` (the harness compiles without `UNITY_EDITOR` and `DEVELOPMENT_BUILD`, as a release player).
- The first `Fire` of a subscribed signal allocated after `SignalBus.Prewarm<T>()` (issue #77): the metrics trace label `SignalTraceLabel<T>` was built on the first metered fire (280 B in the host harness; Wickling fired an empty signal at start-up to pay it). `Prewarm<T>` builds it; harness GCAudit GCA6 locks the first fire after `Prewarm` at 0 B.
- A model or service the game built itself got no `[Inject]` members and no lifecycle (issue #69): `BindModelInstance` and `BindInstance` only stored the object, so an `IReactiveModel` built with game values never ran `OnBind` and could not fire signals (ChipCrisis's `RatingModel`), and a service built with game values got no `InitializeAsync` (Wickling moved its services' start-up into constructors). `BindModelInstance` now injects the model and runs its `OnBind` with the other models; the new `IContextBuilder.BindServiceInstance<TInterface>(instance)` injects, initialises and disposes a service the game built, in bind order, as `BindService` does; `BindInstance` logs a warning when it is given an `INexusService`. `IContextBuilder` gains a member: another implementation must add it. PlayMode `InstanceBindingLifecycleTests` (a built service after a bound one; a non-service refused; a built model injected before its `OnBind`, which ran 0 times before the fix).
- A screen opened by `UIManager` never bound when the scene held two Roots (issue #67): screens are created under the shared `[Nexus_UICanvas]`, which has no `Root`, so the screen's view fell back to the scene's single Root and gave up with "Multiple Root instances found" next to an app Root and a scene Root; its mediator never bound (ChipCrisis kept its own UI stack for this). `UIManager` now creates a screen under an inactive holder and marks it with the context of the UIManager that opened it (`ScreenOwner`, internal) before its views run `OnEnable`; a view with no Root among its parents registers with that context, on the first open and on every reopen from the pool. Screens of a UIManager without a context (built by hand, as in the EditMode tests) keep the old lookup. PlayMode `UIManagerTwoRootsTests` (an app Root and a scene Root; open, close, reopen), which logged the error before the fix.
- A public type declared under `#if DEVELOPMENT_BUILD || UNITY_EDITOR` broke every release player build (issue #85): the binder is generated from the Editor's assemblies, so it named the type in a constructor factory, an injector, a clearer and `PreserveMembers`, and a release player, where the type does not exist, failed with CS0234 / CS0246 at the end of the build (Wickling made its development tools `internal` to avoid it). The generator now reads each type's declarations in its assembly's source files and writes every line that names the type under the type's own condition; a symbol only the type's assembly defines (an asmdef's `versionDefines`) is replaced by its Editor value instead of being copied, and a partial type with one unconditional part is named unconditionally. An `[Inject]` member under its own `#if` inside an unconditional type is not covered. Regenerate the binder (**Nexus > Generate AOT Binder**) to pick it up. EditMode `BinderConditionTests` (the type's condition, a generic argument, `#elif`, a partial type, a version define); the development project holds a development-only fixture, `Assets/Scripts/Verify/DevOnlyProbe.cs`, and its release Standalone Mono and IL2CPP builds (`tools/unity-verify`) pass, where the Mono build failed with five CS0246 errors in the binder before the fix.
- A stale generated binder left new `[OptionalInject]` members null without a word, and the generator dropped `[Inject(Name = ...)]` on fields, properties and method parameters (issue #81): the runtime check of a generated injector skipped optional members, so `LocalizationService.Options` (#72) and the services' `SettingsStores` (#71) stayed null in a player whose binder predated them; and the generator emitted `di.Resolve<T>()` without the binding name (and `TryResolve<T>()` for a named optional constructor parameter). An optional member the container can supply but the injector left null now marks the injector stale (reflection takes over, with the warning), and every generated member and parameter resolves its named binding as reflection does. EditMode `StaleBinderFallbackTests.BoundOptionalMemberTheStaleInjectorSkippedIsInjectedByReflection`, harness CG1 (`CodeGenNamed`: named field, property, optional property and method parameter, emitted, compiled and resolved).
- A saved language code with capitals read every text in English (issue #82): `LocalizationService` read `NT_Language` as saved, while tables are keyed lower-case, so a game that saved `pt-BR` itself found no table (the culture, which ignores case, hid it). The saved code is now lower-cased like `SetLanguage`'s. PlayMode `LocalizationServiceTests.SavedLanguageWithCapitals_ReadsItsTable`.
- `EncryptedStorageService` lost everything after a backup restore on another phone (issue #79): its seed is XORed with a key derived from `SystemInfo.deviceUniqueIdentifier`, so on a new phone (Android Auto Backup restores PlayerPrefs and the files) the seed decoded without an error into a different one and every value failed HMAC verification and reverted to its default. `new EncryptedStorageService(salt, StorageKeyBinding.App)` binds the seed to the app id and salt instead; its first run takes over the device-bound seed written on that phone, so existing data stays readable after the switch and after a restore. `StorageKeyBinding.Device` stays the default, so nothing changes for existing data until a game opts in. (Unity's `AsyncOperation`/`ResourceRequest` is not natively awaitable — no `GetAwaiter` — so a direct `await request` would not compile; the TCS bridge matches the existing `GameSaveManager`/`WindowManager` pattern.)

Without `QueueDrainer`, the context's `HybridQueue` was NEVER drained in the demo (queued signals/commands silently never ran); without `MetricsSampler`, the game never recorded FPS/memory/GC metrics, so the Performance Dashboard (which reads `PerformanceMonitor.GetMetric("FPS")`) would read a flat 0.0. Both components are now added to `GameRoot`.
- **Reentrancy Counter Drift (SignalBus.cs)** — Fixed `s_stackDepth` and `s_asyncStackDepth` counter drift when reentrancy limit exceeded. Now uses `enteredDepth` flag to ensure counter is only decremented if increment succeeded, preventing negative drift across nested dispatches.

- **Decorator Closure Allocation (CommandExecutor.cs)** — Restored the non-allocating dispatch call for the generic sync path AND eliminated the same closure class in the async/object paths: an inline lambda capturing `signal`/`command` (both referenced from catch/finally) made Roslyn hoist a closure display-class to method entry (~56 B per dispatch on the sync path, caught by the zero-GC harness and confirmed via IL dump). - **Async Depth Guard Boxing (SignalBus.cs)** — the async reentrancy guard stored depth in `AsyncLocal<int>`, boxing a fresh int on every entry AND exit (~192 B/op standalone; ~96 B/dispatch on `FireAsync`). The box is shared by every flow derived from one root execution context — exactly the tree-depth semantics a runaway-chain guard needs — while independent roots (separate `FireAsync` calls from sync code) still get isolated boxes. ### Fixed
- **`BigDouble` value-equality contract (B1/B2/Or3)** — `Equals` previously compared mantissas with a `1e-12` tolerance while `GetHashCode` used the raw `Mantissa` and `CompareTo` used the `double` default comparison, so equal values could hash differently and an `Equals`-positive pair could `CompareTo != 0` (breaking `SortedSet`/`Dictionary`/sorting invariants). `Equals` is now exact (`Exponent == other.Exponent && Mantissa == other.Mantissa`), `GetHashCode` stays `HashCode.Combine(Mantissa, Exponent)` (now consistent), and `CompareTo` gained early zero/sign branches plus exact `Mantissa.CompareTo`. `operator *` / `operator /` also saturate exponent arithmetic (`SaturateAddExponent`/`SaturateSubExponent`) so a huge product no longer overflows the `long` exponent and silently corrupts the value.
- **`GameSaveManager` main-thread context capture (İ2)** — `_mainThreadContext` was captured in a field initializer (`= SynchronizationContext.Current`) at *type-load* time, when `SynchronizationContext.Current` is still null, so `LoadAsync` could never re-enter the Unity main thread. It is now a lazy `MainThreadContext => _mainThreadContext ??= SynchronizationContext.Current` accessed at first `LoadAsync` call (guaranteed on the main thread), fixing the dead capture.
- **`NexusDI.Dispose()` fire-and-forget ordering (İ3)** — async singletons were disposed one fire-and-forget task per instance (`_ = instance.DisposeAsync()`) launched in parallel with no ordering, so registration-dependency order was lost and continuations could re-capture the disposing thread's `SynchronizationContext`. `Dispose()` now collects `IAsyncDisposable` instances and runs them through a single ordered thread-pool chain `DisposeAllAsyncInBackground` (sequential `await ...ConfigureAwait(false)` per item with per-item error capture); the deterministic `DisposeAsync()` path remains for callers that can await.
- **`ContextLifecycleOrchestrator` await re-capture (İ3)** — `StopAsyncInternal` now `await ...ConfigureAwait(false)` so the stop continuation stays on the thread pool instead of hopping back to the caller's context.
- **Recovery abort exception identity (İ4)** — the recovery engine's Abort / retry-limit throws were plain `InvalidOperationException` and the strategy-failure `catch` filtered on `InnerException == ex` object identity, which misfires when a strategy legitimately wraps the original error. A typed `NexusRecoveryAbortException : InvalidOperationException` (preserving the existing catch/assert contract) is thrown by both paths and the filter now matches on type (`when (!(strategyEx is NexusRecoveryAbortException))`).
- **`GameStateMachine` cancellation terminal state (Or1)** — a bare `catch (OperationCanceledException)` in the error-state recovery path left `_currentState` stale after a cancelled recovery. It now reaches the same terminal `null` state (guarded by the transition sequence) as the inner-exception path, preventing a stale "failed-from" state leak.
- **Anti-Cheat Integrity Canary (`SecureObservableProperty.cs`)**: Fixed dead-code branch in tamper detection so canary failures log security warnings and reset tampered values to defaults.
- **Encrypted Storage Seed Exception Logging (`EncryptedStorageService.cs`)**: Replaced bare `catch` in seed decoding with explicit `catch (Exception ex)` and warning log before fallback seed regeneration.
- **Command Injection Performance (`CommandRegistry.cs`)**: Optimized signal injection setters using compiled `System.Linq.Expressions` to eliminate `FieldInfo.SetValue` reflection overhead in hot paths.
- **Service Dependency Property Injection (`NexusService.cs`)**: Changed `Context` and `SignalBus` property setters from `private set` to `protected set` for property injection compatibility.
- **Domain Lifecycles Execution (`ContextLifecycleOrchestrator.cs`)**: Enabled dual execution of `IAsyncStartable` and `IStartable` (and stoppable equivalents) when a domain object implements both contracts.

### Security
- **DI validation runs in ALL build targets (A10)** — the Configure-time `ContextBuilder.Validate()` call was previously compiled out under `UNITY_EDITOR`, so production builds silently skipped every check (missing dependencies, constructor explosion, and the A8 captive-dependency rule) and left `[Inject]` fields null with no diagnostic. Validation now runs in every build, is logged (never throws), and can be disabled for projects that intentionally defer bindings past Configure via the new `ContextBuilder.ValidateOnStartup` flag (default `true`).
- **ErrorCollection grouping counters bounded (A10)** — `s_errorGrouping` (unique `category:message` → count) previously grew without bound even though the error bag is capped at `s_maxErrors`, so long sessions with dynamic error messages (URLs, ids, filenames) leaked memory. When unique keys exceed 4096 the counters are rebuilt from the retained bag; `Count` now reflects occurrences among retained entries rather than cumulative-ever.
- **Async in-flight overflow throws in ALL builds (A9)** — `CommandExecutor`'s `MaxInFlightAsyncCommands` guard previously logged and silently dropped the command in Release while the caller's async chain completed "successfully"; it now throws `NexusAsyncOverflowException` unconditionally (same principle as the A8 reentrancy guard), and the guard is unified into a single `EnterAsyncInFlight()` used by all four async dispatch paths — including composite async commands, which previously bypassed the cap entirely.
- **NetworkMonitor latency history is thread-safe (A9)** — `s_latencyHistory` and the shared `ConnectionStatus` were written from network/background threads and read from the game/editor thread on a plain `Dictionary` (the same BUG-17 race `PerformanceMonitor` already fixed). All access is now guarded by a dedicated `s_historyLock`.
- **Reentrancy guard throws in ALL builds (A8)** — `SignalBus` no longer silently returns on `MaxStackDepth` overflow in Release/development-less builds; the `#if UNITY_EDITOR || DEVELOPMENT_BUILD` guard was removed from both the sync and async dispatch paths, so a runaway signal chain now always throws `NexusReentrancyException` (skill checklist §7) instead of hiding state corruption.
- **Atomic save writes everywhere (A8)** — `GameSaveManager` now publishes saves with a single overwrite-rename (`File.Replace`, fallback `File.Move`) instead of the delete-then-move pair that left a crash window where the only good save was already deleted (skill checklist §4.1).
- **Non-blocking teardown (A8)** — `Context` now implements `IAsyncDisposable` (`DisposeAsync()`); the synchronous `Dispose()` path no longer blocks the Unity main thread on `IAsyncDisposable` singletons — async disposal is scheduled on the thread pool with error capture (skill checklist §3.1). Callers that can await should prefer `await context.DisposeAsync()`.
- **Hardware-tick offline anti-cheat (A8)** — `OfflineTimeCalculator` now stores a hardware monotonic tick (`Stopwatch.GetTimestamp() * 1000 / Stopwatch.Frequency`, ms since boot) alongside the wall clock and clamps offline rewards to the hardware-measured elapsed time, closing the forward-clock hole (skill checklist §4.1). On reboot (monotonic reset) it falls back to wall-clock-only validation, still capped.
- **Captive-dependency validation (A8)** — `ContextBuilder.Validate()` now reports `DiValidationIssueType.CaptiveDependency` when a singleton service captures a transient (non-singleton, non-factory) dependency in its constructor or `[Inject]` members (skill checklist §2.2).

### Security
- Added `SecureObservableLong` (XOR-masked RAM obfuscation, mirroring `SecureObservableInt`) and migrated `EconomyService` balances to it — currency values are no longer stored as plain `long` in memory, closing the anti-cheat gap flagged for RAM scanners (GameGuardian/CheatEngine).
- Added `SecureObservableFloat` (XOR-masked RAM obfuscation for IEEE-754 bit patterns, mirroring `SecureObservableInt`/`SecureObservableLong`) and migrated `AdService` interstitial cooldown + last-show timestamp to it — a memory scan can no longer zero the cooldown or backdate the timer to spam interstitials.
- `IapService` editor/dev mock ownership is now guarded by a **salted, rotating-mask checksum** over `_mockOwnedProducts` — a RAM scan (GameGuardian/CheatEngine) can append a fake product ID to the HashSet, but `IsProductOwned` recomputes the checksum before every read, detects the mismatch, wipes the tampered set and denies the forged ownership (fail-closed). Hardening beyond the original session-stable hash: the checksum is folded with a per-instance salt (`_mockOwnedSalt`) and XOR-masked by `_mockOwnedMask` which rotates (`*31+17`) on every successful verify — so value-scans fail across instances and snapshot-replay of an observed (checksum, mask) pair is detected on the next read. Still deterrence, not a security boundary: the real ownership gate is the release `#else` path that never trusts the mock set.
- `ProgressionService` level data migrated to `SecureObservableInt` — `CurrentLevel`/`MaxUnlockedLevel` are no longer plain `int` in RAM.
- `EconomyService.Earn` now clamps at `long.MaxValue` instead of overflowing to a negative balance.
