> **Who this is for:** everyone who ships a game with `com.nexus.ads`. Read before enabling a provider.

# Policy compliance register

Every platform the package can connect to has policies a publisher must follow. This register lists,
per platform, the official policy page, the day it was read, the rules that apply to a mobile game
with rewarded and interstitial ads, and where each rule lives in the package. The platform's current
official text always wins over this file; when a rule here and the page disagree, open an issue in
this repository.

Read date for every page below: **2026-10-24**. A Turkish translation is in
[POLICY_COMPLIANCE_TR.md](POLICY_COMPLIANCE_TR.md).

## How a rule is covered

| Marker | Meaning |
|---|---|
| **Code** | `PolicyGuard` (in `Nexus.Ads.Core`) blocks the call at runtime. The block cannot be turned off; placement and remote values are clamped to the guard's floors. Every block raises a `PolicyViolation` event. |
| **Validator** | `AdsValidator` (editor, `RunCli`, pre-build hook) reports `pass`, `warn` or `fail` per check from the project's settings and a project probe; the check ids in parentheses are the ones in the package README. |
| **Developer** | Cannot be enforced by code; listed in the setup wizard's checklist and here. |
| **SDK** | The mediation or network SDK renders the ad and owns the behaviour (close button, timers); the package never touches the ad view. |

Rule names in the **Package** column are the `PolicyGuard` rule identifiers the Phase 2 code and tests
use (issue #10).

| Rule (official wording, shortened) | Package |
|---|---|
| "Publishers may not click their own ads"; "Testing your own ads by clicking on them is not allowed." | **Developer**: never tap a live ad. **Code** `TestModeRequired`: development builds load only Google's sample ad units; **Validator** fails a Test tab that differs from Google's sample ids (`keys.test.official`) and a Release tab that carries them (`keys.release.testdata`). |
| "If a publisher opens additional accounts, the accounts will be flagged as duplicates." | **Developer**: one AdMob account. |
| Invalid traffic: "Clicks or impressions generated by publishers clicking on their own live ads", "Publishers encouraging clicks on their ads"; "it is your responsibility as the publisher to ensure that the traffic on your ads is valid". | **Developer**: never ask anyone to tap; never hand a build with live ad units to testers. **Code** `UnregisteredDevice` (see the LevelPlay/MAX rows: a development build never requests live ads on an unlisted device). |
| "Do not place interstitial ads on app load and when exiting apps"; interstitials "should only be placed in between pages of app content"; ads cannot run while the app is in the background. | **Code** `InterstitialNaturalBreakOnly` (a placement without `NaturalBreak` cannot show an interstitial), `NoAdInBackground`. |
| "You should place no more than one interstitial ad after every two user actions"; no interstitial immediately after a previous one closed; not after every click. | **Code** `InterstitialFrequency` (minimum gap between interstitials, first-show delay, per-session and per-day caps; the game adds no interstitial of its own). |
| "Ads cannot appear suddenly while a user is absorbed in a task, such as playing a game". Recommended: before the "Next level" button, pre-loaded. | **Code** `InterstitialNaturalBreakOnly`; preload after initialization and after every show is the controller's default. |
| Rewarded ads "must only be served after a user affirmatively and unambiguously opts in"; "clear, accurate and conspicuous disclosure of the action(s) required and reward(s) offered"; "must deliver the promised reward(s) to the user upon completion". | **Code** `RewardedOnRequestOnly` (no rewarded show without a user request; reward granted once, only on the SDK's reward callback). **Developer**: the button states the reward and the amount. |
| Ad refresh "may not be set to a value outside of the range specified in the SDK". | **Code** `NoAutomaticRequests` (requests come only from preload and the retry policy; no refresh loop). |
| Families: apps that include children "must use a Google Play Families self-certified ads SDK or mediation platform"; for mediated requests "set the age treatment to CHILD and set max_ad_content_rating to G for every ad request". | **Code** `ChildSettingsForwarded` (one child-directed flag and content rating in `AdsSettings`, passed to every provider). **Validator** warns when a child-directed app has an adapter of a network that is not on Google's self-certified list or forbids children's apps (`child.networks`, detected by adapter package and folder names; table below). |
| Consent ([Privacy and messaging](https://developers.google.com/admob/unity/privacy) and [Targeting](https://developers.google.com/admob/unity/targeting), read 2026-10-24): "You should request an update of the user's consent information at every app launch, using Update()"; `CanRequestAds()` may be checked "Immediately after you have called Update()" because "The UMP SDK might have obtained consent in the previous app session"; age treatment: `AgeRestrictedTreatment` "replaces the deprecated" `TagForChildDirectedTreatment` and `TagForUnderAgeOfConsent`, and `Child` stands for both. | **Code** `NoRequestBeforeConsent`, `ChildSettingsForwarded`: `AdMobProvider` runs the UMP update and form on every launch before the SDK starts (ads load at once when consent from an earlier session allows it) and sends `AgeRestrictedTreatment.Child` for the child-directed or under-age flag. |
| AD_ID: "update your app to GMA SDK 20.4.0+, which will automatically have the permission declared"; Play requires the declaration for apps targeting Android 13. | **Validator** warns when a custom `AndroidManifest.xml` lacks `com.google.android.gms.permission.AD_ID` on an Android 13+ target (`android.adid`); the merged manifest exists only after a build, so the SDKs' own declarations are not visible to it. |
| Test ads: register a device "in code by adding its ID to RequestConfiguration.TestDeviceIds"; "remove the code that sets these test devices before you release your app"; "If you click on too many ads without being in test mode, you risk your account being flagged for invalid activity." | **Code** `TestModeRequired`: a development build reaches AdMob only with Google's sample units, so every device gets test ads; `AdMobProvider.SetTestDevices` passes Google-format ids to `RequestConfiguration.TestDeviceIds` only while the configuration runs on sample units; **Validator** fails a Release tab with sample units (`keys.release.testdata`); test devices live on the Test tab only, and `ProviderGate` refuses a release configuration that carries any (`TestModeRequired`). |

([Android quick start](https://developers.google.com/admob/android/quick-start),

## PolicyGuard rule map

The rules the brief asked for plus the unknown-placement rule, each tied to the policies above. Numeric floors are code, not this
document; they are set and tested in `Nexus.Ads.Core` (issue #10) and may be tightened by a game,
never loosened.

| Rule id | What the guard blocks | Policies |
|---|---|---|
| `RewardedOnRequestOnly` | Structural: the only show path is `AdController.Show(placement)` and there is no automatic show; a placement declared with another format is blocked as `UnknownPlacement`; the reward is granted once per show and only on the SDK's reward callback. | AdMob rewards policy; Unity Rewarded Inventory Policy; Pangle. |
| `InterstitialNaturalBreakOnly` | An interstitial on a placement without `NaturalBreak`. The guard reads only that flag: the game declares its natural breaks, app exit and gameplay are not detected, and the first seconds of a session are `InterstitialFrequency`. | AdMob disallowed implementations; Play Ads policy; Unity Placement Policy; Pangle. |
| `InterstitialFrequency` | An interstitial inside the minimum gap, inside the first seconds of a session, over the per-session or per-day cap, or right after a rewarded ad; for every format (rewarded and banner too), a show before its placement's `FirstShowAfterSeconds`, inside its cooldown or over its session or day cap. | AdMob "one interstitial after every two user actions"; Play "repeatedly". |
| `NoStackedAds` | A rewarded or interstitial show while a full-screen ad is open (a banner may still show). Loading is not blocked: while an ad shows, the controller does not reload that format until it closes; other formats keep loading. | AppLovin visibility rule; Play Families "multiple ad placements". |
| `NoAdInBackground` | A show while the app is not visible. While hidden the controller also starts no load and cancels pending retries; it resumes them when the app is visible again (a load already in flight completes). | AdMob; Unity Placement Policy. |
| `NoRequestBeforeConsent` | A request before the consent flow finished where consent is required; privacy options stay reachable from the menu. | AdMob: the UMP flow of `AdMobProvider` on every launch (#14); LevelPlay: the same UMP flow (`UmpConsentFlow`) run by the bootstrap before LevelPlay starts when `com.nexus.ads.admob` is installed, whose consent LevelPlay reads, or the game's own `IConsentFlow` registered with `AdsBootstrap.RegisterSharedConsentFlow`, which forwards its answer with `SetGdprConsent`; the ad settings' `Consent` names which, the bootstrap starts no ads while the named flow is not registered, and the validator fails a release build that names none (`consent.form`, #63, #154); the MAX consent page is read with its provider. |
| `ChildSettingsForwarded` | A provider started without the child-directed flag, under-age flag and content rating from `AdsSettings`. | AdMob Families; Play Families; AppLovin children rule; Unity Content Policy; InMobi COPPA. |
| `SingleMediation` | A second mediation provider in the same session. | AppLovin "single mediation integration". |
| `NoAutomaticRequests` | A request that does not come from preload or the retry policy. | AdMob refresh rule; AppLovin invalid requests. |
| `NoAdViewInterference` | The package never hides, overlays, resizes or alters an SDK ad view or its close button. | Play 15-second close rule; AppLovin, Pangle, Chartboost, Meta "rendered as received". |
| `TestModeRequired` | A development build without the provider's test mode or Google's sample units; a release build with them. | AdMob test ads; MAX test mode; LevelPlay test devices. |
| `UnregisteredDevice` | A live SDK request from a development build on a device that is not in the Test tab's device list (the simulator provider runs instead). | Invalid-traffic rules of every platform. |
| `UnknownPlacement` | A placement name that is not declared in the settings, or declared with another format, for every format. | Decision 4 of issue #8; keeps the generated constants the only way to name a placement. |

## Rules the package cannot enforce

The setup wizard shows these as a checklist; the publisher confirms each one.

- Never tap a live ad, and never ask anyone to. Test with the provider's test mode or sample units only.
- Never give a release build, or any build with live ad units, to testers, friends or the team.
- One account per platform, registered with the same company details and the Play Console email.
- `app-ads.txt` on the developer website named in the store listing, listing every enabled network (the package generates the file; publishing it is manual).
- Play Console: ads declaration, target audience, Data safety, advertising-id declaration; the Families age screen for mixed audiences.
- A privacy policy URL that names the ad SDKs (and the KVKK notice for Türkiye); the validator warns when the settings field is empty.
- Traffic sources: no bought installs from sources the networks treat as invalid.
