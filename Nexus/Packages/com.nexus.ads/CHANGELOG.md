# Changelog

The changelog of the ad package family: `com.nexus.ads` (core, Unity layer, editor), the provider
packages (`com.nexus.ads.levelplay`, `com.nexus.ads.max`, and the `Nexus.Ads.AdMob` provider assembly of
`com.nexus.ads.admob`, whose legacy `AdMobAdapter` stays in the core's changelog until it is retired) and
`com.nexus.ads.bridge.nexus`. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
`package.json` is the released version, everything newer is under Unreleased. The plan is
[issue #8](https://github.com/CevatAYDN/GameContainer/issues/8).

## [Unreleased]

### Added
- **AdMob provider** `Nexus.Ads.AdMob` in `com.nexus.ads.admob` (`Runtime/Provider`; issue #14): `AdMobProvider` over the Google Mobile Ads Unity plugin 11.3.0+ as `IAdProvider` and `IConsentFlow`; compiles only with both the plugin and `com.nexus.ads` (`versionDefines` `NEXUS_ADMOB` and `NEXUS_ADS` in its `defineConstraints`), so games that pin the package for the legacy adapter are unaffected. The User Messaging Platform update runs on every launch (consent kept from an earlier session lets ads load while it runs); `AgeRestrictedTreatment.Child` for child-directed or under-age-of-consent settings and the content rating go into `RequestConfiguration` before `MobileAds.Initialize`; `OnAdPaid` becomes `AdRevenue`; the ad inspector is the test suite; `SetTestDevices` takes Google-format test device ids (and the EEA consent geography) and applies them only with Google's sample units. `MIGRATION.md` moves a game from `AdMobAdapter` to the family, with the Gigawatt, Wickling and ChipCrisis map from #8.
- **Validator** check `mediation.admob` (23 check ids): a warning when the Google Mobile Ads SDK is in the project while LevelPlay or MAX is selected (only the selected mediation starts; the SDK still ships).
- **LevelPlay provider** `com.nexus.ads.levelplay` (`Nexus.Ads.LevelPlay`; issue #13): `LevelPlayProvider` over the Ads Mediation package `com.unity.services.levelplay` 9.x (`versionDefines` → `NEXUS_LEVELPLAY`, inert without it): `SetCOPPA` from the privacy flags and the test suite metadata plus adapter debug logging in test mode before `Init`, one `LevelPlayRewardedAd` and one `LevelPlayInterstitialAd` per configured unit, an adaptive banner, impression data as `AdRevenue`, `LaunchTestSuite` as the test tool; a close waits 1.5 s for the reward the SDK may fire after `OnAdClosed`, so a late reward pays once; the consent flow is a pass-through with `SetGdprConsent` / `SetDoNotSell` for a game's CMP. Registered with the bootstrap from a `RuntimeInitializeOnLoadMethod`; `AdsBootstrap.RegisterProvider` hands the factory its scheduler and the provider configuration (a consent flow such as UMP runs before `Initialize` and needs the under-age flag).
- **Debug panel** `AdsDebugPanel` (development builds and the editor; three fingers for a second or F9): provider, gate decision, build, test mode, consent state, the advertising id with a copy button, readiness per placement, the pending reward, the last violations and events, and the mediation's test suite button.
- **Nexus bridge** `com.nexus.ads.bridge.nexus` (`Nexus.Ads.Bridge.Nexus`; issue #12): `NexusAdsAdapter` puts the controller behind `com.nexus.core`'s `AdService` as `IAdNetworkAdapter` + `IAdOutcomeAdapter` + `IAdReadinessAdapter` + `IAdConsentAdapter` (Blocked and NotReady both map to `AdOutcome.NotReady`); `NexusAdsBridge.Connect` registers it under `nexus-ads` and the running provider's name, sets the service's interstitial cooldown to the policy floor, forwards revenue to `AdService.RaiseImpression`, wires `IapAdFreeEntitlement` over `IIapService`, and completes on the bootstrap's `Started` event; `FirebaseAdsRemoteConfig` over `com.nexus.firebase`'s `IRemoteConfigService` in its own assembly (`NEXUS_ADS_FIREBASE`). `AdController` gains `SetAdFreeEntitlement`, `SetRemoteConfig` (late attachment) and `ShowBanner(placement, position)`. EditMode contract tests (10) drive `AdService` through the bridge over the simulator with hand-written ports; a PlayMode test connects before the bootstrap started and takes a reward through the service.
- **Samples** `Samples~/PlainUnity` (ads without Nexus: one component over the static `Ads` facade, in-memory settings when the project has none) and `Samples~/Nexus` (a lifecycle binding `AdService` and the factory, `NexusAdsBridge.Connect`, game code against `IAdService`). `com.nexus.core/docs/ADAPTERS.md` points at the family: editor = simulator, development build = real SDK + Test tab, release = Release tab.
- **Editor** `Nexus.Ads.Editor` (`Editor`; issue #11): `PlatformCatalog` reader over the catalog JSON; `IProjectProbe` with the project probe (SDKs by UPM package or assembly, provider packages, network adapters by package and folder names, EDM, custom Android manifest, target and minimum SDK, link.xml files, consumer manifest, the Google Mobile Ads settings asset); `AdsValidator` as a pure function over settings, tab, platform, probe and catalog with stable check ids (22 at #11), `RunCli` (`-adsTab`, `-adsPlatform`, `-adsReport`; exit 0 / 1 / 2) and the pre-build hook `AdsBuildGuard` (Android and iOS builds only; Test tab for development builds, Release tab otherwise; an ad-free release passes); the Project Settings page (Test/Release tabs per platform, AdMob Test tab locked to Google's sample ids, copy-from-Release for LevelPlay and MAX, device list, placements, floors, privacy, app-ads.txt lines, validator buttons); the setup wizard (catalog rows with status badges and next steps, links, Install SDK, EN/TR steps, developer checklist, project buttons); the Placement Tester window; `AdPlacementsGenerator`, `AppAdsTxt`, `ManifestPinning` and `LinkXml` as text functions. `ProviderStatusResolver` takes the conflicting-SDK input so the badge and the check say the same word. EditMode tests (22 at #11) lock the validator rules through a fake probe, the generator, the pinning transform and the catalog shape.
- **Durable reward receipt** (`AdController.PendingReward`, `AcknowledgeReward`; the brief's reward-integrity row): the receipt is written to `IPacingStore` before the show result is delivered and survives a kill; `AdRewardedButton` acknowledges after its listeners ran. `DeviceIdentity` attaches the JNI thread before asking Google Play services for the advertising id.
- **Engine-free core** `Nexus.Ads.Core` (`Runtime/Core`, `noEngineReferences: true`, no reference to Unity or `com.nexus.core`; issue #10): `AdPlacement`, the only-tightenable `AdPolicy` floors (gap, first-show delay, gap after rewarded, per-session and per-day caps, session resume gap), `PolicyGuard` with the 13 rule ids of `PolicyRules` (`UnknownPlacement` blocks an undeclared or wrongly typed placement name), `SessionTracker` (session reset after the resume gap, per-day counters in `IPacingStore`), `AdController` (consent first, one preloaded ad per used format, reload after every show, `RetryPolicy` back-off 2/4/8…64 s paused while hidden, reward delivered once and only on the SDK's reward callback, kill switch and ad-free entitlement answer NotReady without a violation, remote configuration only tightens), `ProviderGate` (editor = simulator; release build refuses test mode, test devices and sample units; development build needs test mode or published test data and runs the simulator on an unlisted device), `MediationLock` (one mediation per process, the simulator exempt), the scenario-driven `SimulatorProvider` (no fill, load failure, show failure, closed early, slow load, consent refused; interactive for an overlay), and the ports the host implements (`IAdProvider`, `IConsentFlow`, `IAdFreeEntitlement`, `IAdsRemoteConfig`, `IAdClock`, `IAppVisibility`, `IMainThread`, `IAdScheduler`, `IPacingStore`, `IAdTelemetry`). Proven by the host harness suite `AdsCoreSuite` (86 checks, run by the pre-commit hook), which also scans the core sources for engine references.
- **Unity layer** `Nexus.Ads.Unity` (`Runtime/Unity`; issue #10): `AdsSettings` asset with Test and Release tabs (editor and development builds read Test, release builds read Release; the mapping is fixed), the shared test device list, placements, policy floors and privacy flags; `ProviderStatusResolver`, the only place that computes NotInstalled / Inactive / TestOnly / Active / Invalid per platform; `AdsBootstrap` (settings → build kind → advertising id off the main thread → gate → registered provider or simulator → controller; pauses audio and time between open and close); the static `Ads` facade for projects without Nexus; `SimulatorOverlay` (IMGUI full-screen fake ad with reward, close and fail buttons); `AdRewardedButton` (visible only while its placement can show, pays once); the port implementations (`UnityAdClock`, `UnityAppVisibility`, `UnityMainThread`, `UnityAdScheduler` on unscaled time, `PlayerPrefsPacingStore`, `UnityAdTelemetry` fan-out). EditMode tests (14) lock the settings mapping, the derived required fields, the floor clamp, the resolver's five statuses and the conflicting-SDK input; PlayMode tests (4) lock the editor simulator path with the pause, the first-minute interstitial block, the unscaled scheduler and the button.
- **Policy register and platform catalog** (Phase 1, issue #9): `docs/POLICY_COMPLIANCE.md` (+ `_TR.md`) maps every platform's official policy pages, read 2026-10-24, to a `PolicyRules` id, a validator check or a developer checklist item and records Google's Families self-certified status per network; `Editor/PlatformCatalog.json` carries the registration and documentation links, Google's sample ids with their source, the UPM package names, registries and defines of the LevelPlay, MAX and AdMob SDKs, and the setup steps in English and Turkish.
