# Changelog

The changelog of the ad package family: `com.nexus.ads` (core, Unity layer, editor), the provider
packages (`com.nexus.ads.levelplay`, the `Nexus.Ads.AdMob` and `Nexus.Ads.AdMob.Firebase` assemblies of
`com.nexus.ads.admob`, whose legacy `AdMobAdapter`, removed in #14, has its history in the core's changelog) and
`com.nexus.ads.bridge.nexus`. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
`package.json` is the released version, everything newer is under Unreleased. The plan is
[issue #8](https://github.com/CevatAYDN/GameContainer/issues/8).

## [Unreleased]

### Added
- **The analytics consent over Google's consent form** (`com.nexus.ads.admob`, issue #87): `UmpAnalyticsConsent`, the `IAnalyticsConsent` that `com.nexus.firebase`'s services read (`FirebaseBindings.Bind<UmpAnalyticsConsent>(builder)`), in the new assembly `Nexus.Ads.AdMob.Firebase`, compiled only with `com.nexus.firebase` installed too. Wickling and ChipCrisis each kept a copy with a different rule: Wickling read TCF purpose 1 as the analytics choice, ChipCrisis refused it always. Rule (b), the advisor's decision delegated by the owner: Google maps no TCF purpose to `analytics_storage`, so the form answers nothing about analytics, and where consent is required nothing is sent, analytics and Crashlytics (#78) alike. The state is UMP's status, read at start and again on `IAdService.ReadyChanged`; `Changed` fires and a line is logged only when it changes. EditMode `UmpAnalyticsConsentTests` (5 cases) in `Nexus/artifacts/admob-20261028/AdMobFirebaseConsumer` with Google Mobile Ads 11.6.0: EditMode 63 / 63 / 0 / 0; with the choice set to granted, the case for an answered form fails. The device line is a game's re-pin run.

### Fixed
- A game's generated AOT binder no longer registers the bridge's or `Nexus.Ads.AdMob.Firebase`'s types (core issue #110). The game's binder named them, so removing one of these types broke the game's binder compile, as `AdMobAdapter` did in #14. Those types now take the reflection path. `com.nexus.ads.bridge.nexus` and `com.nexus.ads.admob` each ship a `Runtime/link.xml` that preserves `Nexus.Ads.Bridge.Nexus` and `Nexus.Ads.AdMob.Firebase` whole, with `ignoreIfMissing`. Details are in the core CHANGELOG.
- Every player build printed two `CS0414` warnings from `Runtime/Unity` (issue #103): `AdsDebugPanel._touchStart` is read only under `ENABLE_LEGACY_INPUT_MANAGER` and is now declared there too, and `SimulatorOverlay._placement` was set and never read, so it is gone; the overlay's summary named a placement it never drew and now names the scenario it does.
- `ReadyChanged` (and `Ads.OnReadyChanged`, `IAdService.ReadyChanged` through the bridge) was not raised when a time rule of the guard ran out (issue #95): a placement's cooldown and first-show delay, the first-interstitial delay, the gap after an interstitial or a rewarded ad, and a day cap at the UTC day change turned `IsReady` true with no event, so a UI that follows the event, `AdRewardedButton` included, stayed hidden until something unrelated happened. Polling instead is no way out: it reaches the SDK each time the 0.1 s answer reuse runs out, a LevelPlay JNI call on Android (in ChipCrisis, three mediators polling `IsRewardedAvailable` allocated in 672 of 3606 frames on the phone, its `docs/RELEASE_GATES.md` §3). `PolicyGuard.SecondsUntilPacingEnds`, `SessionCapReached` and `DayCapReached` answer from the same rules `Check` uses, and `AdController` arms one `IAdScheduler` wake for the loaded placement whose windows end first (a day cap compares the UTC day once a minute); the wake raises the event once without asking the provider and is cancelled on `Dispose`. `AdsCoreSuite` PW1–PW7 fail on the old code. `com.nexus.core`'s own `AdService` cooldown without the bridge had the same gap; its fix is in the core changelog (issue #99).
- The debug panel and the simulator overlay allocated every frame while hidden (issue #83): `AdsDebugPanel` (every non-Release build) and `SimulatorOverlay` kept an enabled `OnGUI` that returned at once, and IMGUI allocates for an enabled `OnGUI` anyway (Wickling measured 61,824 B in 168 of 169 frames on a POCO X6 Pro). The panel now draws from a second component that is enabled only while it is open (the three-finger hold, F9 and `Toggle()` are unchanged), and the overlay is enabled when a show opens and disabled when it closes. PlayMode `AdsBootstrapPlayModeTests.OnGUI_RunsOnlyWhileThePanelIsOpenOrAShowIsOpen`.
- Prepare Android counted a disabled `com.google.external-dependency-manager` stub as the dependency resolver (issue #61): Gigawatt, Wickling and ChipCrisis embed one beside Firebase (a package folder with `.edm_dummy`), and their only working resolver arrives with `com.google.ads.mobile`, so a game that dropped that SDK for LevelPlay would see the resolver step Done and `android.edm` pass with no resolver at all; adding Google's package from OpenUPM would not help, the embedded stub shadows it. The probe no longer counts the stub, and Prepare Android adds `com.unity.external-dependency-manager` from the Unity registry when the stub is there. EditMode test `ADisabledEdmStub_IsNoResolver_AndPrepareAndroidAddsUnitysResolverInstead`.
- With LevelPlay selected, the validator checked the Google Mobile Ads App ID only when AdMob was the mediation (issue #63), yet that SDK's Android side stops the app at launch without one whichever mediation runs: `android.admob.appid` now fails such a build without an App ID, and a release with Google's sample App ID.
- Documents (issues #57, #60): the bridge, `Nexus` sample and AdMob READMEs listed packages that do not resolve in a bare project (`com.nexus.core` was missing; a bare project failed with `Package [com.nexus.core@0.5.0] cannot be found`, `Nexus/artifacts/integration-20261025-nexus`); `MIGRATION.md` said `manifest.pins` covers `com.nexus.core`; the LevelPlay README put PlayMode tests in EditMode, missed the Gradle properties template and gave the rewarded close grace period to interstitials; the policy register's `RewardedOnRequestOnly`, `InterstitialFrequency`, `InterstitialNaturalBreakOnly`, `NoStackedAds` and `NoAdInBackground` rows (EN and TR) described more or less than `PolicyGuard` and `AdController` do; the README named the overlay, the simulator cases, the `AdPolicy` tests and the `android.admob.appid` severity wrongly; `com.nexus.ads.max` is marked planned.
- `AdsBootstrap` logged nothing when it started the real SDK (issue #52): the provider path had no line, so logcat could not tell a listed device's SDK start from a silent failure, and `tools/device-acceptance` could not check which side of the gate a device was on. The bootstrap now logs one line per start in every build and every mode, without ids: `[Nexus Ads] started mode=… mediation=… gate=… rule=… testMode=on|off`. `AdsBootstrapPlayModeTests.Start_LogsOneLine_WithTheModeTheGateAndTestMode` fails on the old code.
- `AndroidSetup.PrepareCli` wrote its result with `Console.WriteLine`, and in one dry run none of those lines reached the `-logFile` while the resolver's `Debug` lines from the same process did (issue #50; not reproduced in five further runs, cause unknown). The CLI's lines now go through Unity's logger without a stack trace, as `AdsValidator.RunCli`'s do.
- A LevelPlay project prepared by Prepare Android logged `Resolution Failed` from the External Dependency Manager on every resolution and every build ("could not enable Jetifier ... without Custom Gradle Properties Template") while Prepare Android reported every step Done (issue #49): the resolver writes the dependencies into the custom main template first and then fails on the missing properties template. Prepare Android now copies Unity's `gradleTemplate.properties` to `Assets/Plugins/Android/` before resolving (catalog field `gradlePropertiesNote`); `AndroidSetupTests` fails on the old code (no such step).
- The one line `AdsBootstrap` writes for a blocked show lost the word `PolicyViolation` in #36, so `tools/device-acceptance` (which counts `[Nexus Ads] PolicyViolation` lines) reported 0 violations whatever the device did (issue #48). The line reads `[Nexus Ads] PolicyViolation <rule> (...)` again; `AdsBootstrapPlayModeTests.BlockedShow_IsLoggedOnce_WithTheTokenTheAcceptanceScanCounts` fails on the old code.
- An unavailable advertising id was treated like any other (issue #42): `ProviderConfig.IsTestDevice` matched an all-zero id (Android's id when ad personalization is off) if it was listed, so every such device got the SDK, and the gate told a device without an id to add itself to the Test tab. An empty or all-zero id never counts as a test device now, and the gate's reason says the id is unavailable; `AdsBootstrap` logs a warning when the id cannot be fetched. `AdsCoreSuite` GT14 fails on the old code (the listed zero id got the SDK).
- A blocked show was written as an error twice in development builds with event logging on, by the telemetry log and by `AdsBootstrap`, and each line opened the Development Console on the device (issue #36). The telemetry log skips violations; the bootstrap writes one line.
- `Ads.IsReady` asked the provider on every call, so a button polled each frame crossed into the SDK each frame and LevelPlay in test mode logged every `isAdReady()` (about two logcat lines per frame with `PlainUnityAdsDemo`; issue #32). `AdController` reuses the provider's answer per format for 0.1 s; `Show` and preloading still ask live and a `Loaded` event drops the stored answer. `AdsCoreSuite` AC40 fails on the old code (100 provider calls for 100 polls).
- Prepare Android logged `resolve: ResolveSync returned False` and, in the same run, reported the resolve step Done (issue #22): the External Dependency Manager's `ResolveSync` answered false while it wrote the dependencies into the main Gradle template (three runs, 2026-10-24 and -25). The line now reports the template, which is what Gradle reads: the markers it names, or the ones it still misses with the resolver's answer and the Force Resolve menu to read its log.
- The LevelPlay install steps had an order a bare project cannot follow (issue #22): the README put Prepare Android before the settings asset it reads (`PrepareCli` exits 2 without it), no install section said that the git URL needs the full 40-character commit hash (a short one fails to clone), and the advertising id for the Test tab was documented only on a running development build. The `com.nexus.ads` README gains an Install section and the advertising id's source on the phone (Google's ads settings page); the LevelPlay README and the setup wizard's LevelPlay steps (EN + TR) go settings first, then Prepare Android twice.
- `com.nexus.ads` did not compile in a project without `com.unity.ugui` (issue #21): `Nexus.Ads.Unity` references `UnityEngine.UI` (`AdRewardedButton`) while `package.json` declared no dependencies, and a project made from Unity 6000.5's bare template has no `com.unity.ugui`, so adding the package by git URL ended in `CS0234` / `CS0246` in `AdRewardedButton.cs`. The package now declares `com.unity.ugui` 2.0.0, as `com.nexus.core` does; `AdsCoreSuite` EF3 fails when a package's non-test asmdef references `UnityEngine.UI` without that declaration.
- `Shown` and `Revenue` events carried no placement on a real provider, and the debug panel named a simulator that was not running (issue #20): `AdController` recorded `Shown` with an empty placement and passed through the empty placement LevelPlay's impression data carries, so the log read `Shown Rewarded ''` and `Revenue Rewarded ''` beside `Rewarded Rewarded 'shop_refill'` and a game's revenue analytics got an empty placement; the controller now fills an empty placement with the one it last showed for that format (revenue arrives after `Closed`), and an idle host's debug panel says `provider: none (no ads run)` instead of `simulator`. Locked by `AdsCoreSuite` AC39, which fails on the old controller.
- Prepare Android left out LevelPlay's Unity Ads adapter (issue #16): it declared the native SDK only, so a prepared build started with a real App Key and answered every rewarded and interstitial request with `509 Mediation No fill`, and the validator passed it. The catalog gains `nativeAdapter` (Unity Ads for LevelPlay); `AndroidSetup.TryAdapter` picks the newest `adapters.UnityAds` version in the package's `LevelPlayVersions.json` whose `ironSourceSdkVersion` range holds the native SDK (5.11.0.0 for 9.5.0), Prepare Android downloads `ISUnityAdsAdapterDependencies.xml`, the resolve step waits for `unityads-adapter` in the template, and the validator gains `android.adapter` (26 check ids). Device run 2026-10-24: without the adapter 509 on every retry; with it a rewarded ad loaded in 2 s and paid, an interstitial closed.
- A store build could run the ad simulator (issue #19): `AdsBootstrap` ran the interactive simulator, overlay and rewards included, and started the controller when the gate blocked with a rule (a release build with test configuration, a development build without test mode) or when the selected provider was not registered (package missing, assembly stripped), although the README called those cases blocked. `ProviderGate.Host` now decides what runs: the simulator only where the gate chose it or while no mediation is selected outside a release build; every other case runs nothing (controller never started, shows answer `NotReady`) and logs the reason as an error. `AdsBootstrap.Mode` exposes the decision. Host harness `AdsCoreSuite` GT10–GT13.
- `LevelPlayProvider` reported a rewarded ad's revenue as `Interstitial` (issue #17): it read the format from the impression data's `AdFormat` string, which the Android SDK sends as `rewarded_video` and the editor SDK as `editor_mock_format`; the format now comes from the ad object that raised the impression. Seen on a device run with LevelPlay 9.5.1; a PlayMode test over the SDK's editor platform locks it (it fails on the old code). The provider's PlayMode tests also destroy the editor SDK's mock ad prefabs after each test: every ad object leaves one in the scene, and the tests' close helper could pick a stale one from an earlier test.
- The IL2CPP linker removed `Nexus.Ads.AdMob` and `Nexus.Ads.LevelPlay` from Android players: nothing references a provider assembly (it registers itself from a `RuntimeInitializeOnLoadMethod`), so a development build with AdMob selected logged "provider package is not installed" and ran the simulator. Both assemblies carry `[assembly: AlwaysLinkAssembly]`; the bootstrap's message names stripping as a cause. Found and verified on a phone (2311DRK48G, Android 16): Google's test ads shown, rewarded paid once, interstitial closed; LevelPlay's SDK started and reached its server.

### Added
- **Google's consent form before LevelPlay** (issue #63): LevelPlay ships no consent form, so nothing asked players in the EEA, the UK and Switzerland. The UMP flow of `AdMobProvider` is now its own `UmpConsentFlow`; `com.nexus.ads.admob` registers it with `AdsBootstrap.RegisterSharedConsentFlow`, and with another mediation selected the bootstrap runs it before that provider initializes (`AdsBootstrap.ConsentFlowFor`); `PrivacyOptionsRequired` and `ShowPrivacyOptions` then come from UMP, and LevelPlay reads the consent UMP stored. `UmpConsentFlow.SetDebugDevices` gives that form test devices and EEA geography in test mode. Validator check `consent.form` (27 check ids) warns when LevelPlay runs without a consent platform; `mediation.admob` passes when `com.nexus.ads.admob` is installed beside LevelPlay. Tests: `ASharedConsentPlatform_RunsBeforeAMediationWithoutAForm_AndTheProviderThatRunsItKeepsItsOwn`, `LevelPlay_RunsGooglesConsentForm_WhenItsPackagesAreIn_AndWarnsWithoutAnyConsentPlatform`, `GoogleSdk_BesideLevelPlay_NeedsAnAppId_AndNoSampleOneInARelease`, and with Google Mobile Ads `AnotherMediation_GetsGooglesConsentForm_ThatAnswersBeforeItStarts`.
- **A bootstrap that waits** (issue #62): `AdsBootstrap` read the advertising id and started the consent flow and the SDK in `Awake`, so a game could not start ads late (Gigawatt at its first offer, Wickling after the first night and never for a pass owner). With `startOnAwake` off (inspector, or `Configure(..., startOnAwake: false)`) nothing touches the id, the consent flow or the SDK until `StartAds()`, which starts once. PlayMode test `StartOnAwakeOff_TouchesNothingUntilStartAds_ThenStartsOnce`, which also found that an `Ads.OnReadyChanged` subscription made before the start missed the first fill (the simulator fills during the start, before the subscription was attached), so an `AdRewardedButton` enabled before the bootstrap stayed hidden in the editor; the late subscriber is now called once when it is attached.
- **What each build does** (`BuildOutlook`, issue #18, first iteration): Project Settings > Nexus Ads, the setup wizard and the debug panel say in plain words what the editor, a development build (listed and other devices) and a release build do with ads. `AdsBootstrap` runs `BuildOutlook.Decide` and every surface shows `Say` of the same decision, so a surface cannot promise an ad the runtime will not run: a release row names the validator when it will stop the build, an AdMob development row says Google's sample units, and a LevelPlay or MAX development row says test ads only if the device is also in the mediation's dashboard, which the package cannot see. The same change corrected prose that said a development build without the provider shows no ads (a device that is not listed runs the simulator). EditMode `BuildOutlookTests`: 9 tests.
- **Prepare Android** (`AndroidSetup`, issue #15): the setup wizard's Android section and one button perform the selected mediation's Android setup from `PlatformCatalog.json` (SDK and provider package at the core's commit, dependency resolver, LevelPlay's native SDK declaration for the version its package names, custom main Gradle template with the catalog's lines, resolution, AdMob App ID); `PrepareCli` runs it from the command line. The validator gains `android.nativesdk` and `android.gradle` (25 check ids), read from the same plan. Proven from two clean projects (LevelPlay, AdMob) built and run on a phone.
- **AdMob provider** `Nexus.Ads.AdMob` in `com.nexus.ads.admob` (`Runtime/Provider`; issue #14): `AdMobProvider` over the Google Mobile Ads Unity plugin 11.3.0+ as `IAdProvider` and `IConsentFlow`; compiles only with both the plugin and `com.nexus.ads` (`versionDefines` `NEXUS_ADMOB` and `NEXUS_ADS` in its `defineConstraints`), so games that pin the package for the legacy adapter are unaffected. The User Messaging Platform update runs on every launch (consent kept from an earlier session lets ads load while it runs); `AgeRestrictedTreatment.Child` for child-directed or under-age-of-consent settings and the content rating go into `RequestConfiguration` before `MobileAds.Initialize`; `OnAdPaid` becomes `AdRevenue`; the ad inspector is the test suite; `SetTestDevices` takes Google-format test device ids (and the EEA consent geography) and applies them only with Google's sample units. `MIGRATION.md` moves a game from `AdMobAdapter` to the family, with the Gigawatt, Wickling and ChipCrisis map from #8.
- **Validator** check `mediation.admob` (23 check ids at #14): a warning when the Google Mobile Ads SDK is in the project while LevelPlay or MAX is selected (only the selected mediation starts; the SDK still ships).
- **LevelPlay provider** `com.nexus.ads.levelplay` (`Nexus.Ads.LevelPlay`; issue #13): `LevelPlayProvider` over the Ads Mediation package `com.unity.services.levelplay` 9.x (`versionDefines` → `NEXUS_LEVELPLAY`, inert without it): `SetCOPPA` from the privacy flags and the test suite metadata plus adapter debug logging in test mode before `Init`, one `LevelPlayRewardedAd` and one `LevelPlayInterstitialAd` per configured unit, an adaptive banner, impression data as `AdRevenue`, `LaunchTestSuite` as the test tool; a close waits 1.5 s for the reward the SDK may fire after `OnAdClosed`, so a late reward pays once; the consent flow is a pass-through with `SetGdprConsent` / `SetDoNotSell` for a game's CMP. Registered with the bootstrap from a `RuntimeInitializeOnLoadMethod`; `AdsBootstrap.RegisterProvider` hands the factory its scheduler and the provider configuration (a consent flow such as UMP runs before `Initialize` and needs the under-age flag).
- **Debug panel** `AdsDebugPanel` (development builds and the editor; three fingers for a second or F9): provider, gate decision, build, test mode, consent state, the advertising id with a copy button, readiness per placement, the pending reward, the last violations and events, and the mediation's test suite button.
- **Nexus bridge** `com.nexus.ads.bridge.nexus` (`Nexus.Ads.Bridge.Nexus`; issue #12): `NexusAdsAdapter` puts the controller behind `com.nexus.core`'s `AdService` as `IAdNetworkAdapter` + `IAdOutcomeAdapter` + `IAdReadinessAdapter` + `IAdConsentAdapter` (Blocked and NotReady both map to `AdOutcome.NotReady`); `NexusAdsBridge.Connect` registers it under `nexus-ads` and the running provider's name, sets the service's interstitial cooldown to the policy floor, forwards revenue to `AdService.RaiseImpression`, wires `IapAdFreeEntitlement` over `IIapService`, and completes on the bootstrap's `Started` event; `FirebaseAdsRemoteConfig` over `com.nexus.firebase`'s `IRemoteConfigService` in its own assembly (`NEXUS_ADS_FIREBASE`). `AdController` gains `SetAdFreeEntitlement`, `SetRemoteConfig` (late attachment) and `ShowBanner(placement, position)`. EditMode contract tests (10) drive `AdService` through the bridge over the simulator with hand-written ports; a PlayMode test connects before the bootstrap started and takes a reward through the service.
- **Samples** `Samples~/PlainUnity` (ads without Nexus: one component over the static `Ads` facade, in-memory settings when the project has none) and `Samples~/Nexus` (a lifecycle binding `AdService` and the factory, `NexusAdsBridge.Connect`, game code against `IAdService`). `com.nexus.core/docs/ADAPTERS.md` points at the family: editor = simulator, development build = real SDK + Test tab, release = Release tab.
- **Editor** `Nexus.Ads.Editor` (`Editor`; issue #11): `PlatformCatalog` reader over the catalog JSON; `IProjectProbe` with the project probe (SDKs by UPM package or assembly, provider packages, network adapters by package and folder names, EDM, custom Android manifest, target and minimum SDK, link.xml files, consumer manifest, the Google Mobile Ads settings asset); `AdsValidator` as a pure function over settings, tab, platform, probe and catalog with stable check ids (22 at #11), `RunCli` (`-adsTab`, `-adsPlatform`, `-adsReport`; exit 0 / 1 / 2) and the pre-build hook `AdsBuildGuard` (Android and iOS builds only; Test tab for development builds, Release tab otherwise; an ad-free release passes); the Project Settings page (Test/Release tabs per platform, AdMob Test tab locked to Google's sample ids, copy-from-Release for LevelPlay and MAX, device list, placements, floors, privacy, app-ads.txt lines, validator buttons); the setup wizard (catalog rows with status badges and next steps, links, Install SDK, EN/TR steps, developer checklist, project buttons); the Placement Tester window; `AdPlacementsGenerator`, `AppAdsTxt`, `ManifestPinning` and `LinkXml` as text functions. `ProviderStatusResolver` takes the conflicting-SDK input so the badge and the check say the same word. EditMode tests (22 at #11) lock the validator rules through a fake probe, the generator, the pinning transform and the catalog shape.
- **Durable reward receipt** (`AdController.PendingReward`, `AcknowledgeReward`; the brief's reward-integrity row): the receipt is written to `IPacingStore` before the show result is delivered and survives a kill; `AdRewardedButton` acknowledges after its listeners ran. `DeviceIdentity` attaches the JNI thread before asking Google Play services for the advertising id.
- **Engine-free core** `Nexus.Ads.Core` (`Runtime/Core`, `noEngineReferences: true`, no reference to Unity or `com.nexus.core`; issue #10): `AdPlacement`, the only-tightenable `AdPolicy` floors (gap, first-show delay, gap after rewarded, per-session and per-day caps, session resume gap), `PolicyGuard` with the 13 rule ids of `PolicyRules` (`UnknownPlacement` blocks an undeclared or wrongly typed placement name), `SessionTracker` (session reset after the resume gap, per-day counters in `IPacingStore`), `AdController` (consent first, one preloaded ad per used format, reload after every show, `RetryPolicy` back-off 2/4/8…64 s paused while hidden, reward delivered once and only on the SDK's reward callback, kill switch and ad-free entitlement answer NotReady without a violation, remote configuration only tightens), `ProviderGate` (editor = simulator; release build refuses test mode, test devices and sample units; development build needs test mode or published test data and runs the simulator on an unlisted device), `MediationLock` (one mediation per process, the simulator exempt), the scenario-driven `SimulatorProvider` (no fill, load failure, show failure, closed early, slow load, consent refused; interactive for an overlay), and the ports the host implements (`IAdProvider`, `IConsentFlow`, `IAdFreeEntitlement`, `IAdsRemoteConfig`, `IAdClock`, `IAppVisibility`, `IMainThread`, `IAdScheduler`, `IPacingStore`, `IAdTelemetry`). Proven by the host harness suite `AdsCoreSuite` (94 check ids, run by the pre-commit hook), which also scans the core sources for engine references.

### Changed
- `com.nexus.ads.admob` declares `com.nexus.ads` instead of `com.nexus.core` (issue #14): the core dependency served only the legacy `AdMobAdapter`, now removed. Prepare Android adds the AdMob provider package alone, as for LevelPlay; the catalog's `providerDependencies` field and the step that added the core next to the provider are gone.
- Project Settings > Nexus Ads shows under the keys where the values come from (the selected provider's setup steps and test-device location from `PlatformCatalog.json`), Prepare Android for the tab being edited, and validator results as one box per failing or warning check with its fix; the wizard shows results the same way (issue #18). The Android plan, which reads project and package files, is rebuilt when the tab, the settings asset or the project state changes instead of on every repaint of the wizard.
