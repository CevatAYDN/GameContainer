# Audit 2026-11-01 (#206)

Full audit of performance, architecture and structure on commit `4b994a5` (main), requested by the owner before
the 0.6.0 release candidate. The audit changed no package code. It filed 57 issues, #207–#263, each with its
location, its reproduction and a fix direction.

## Scope and method

**Packages.** `com.nexus.core` (runtime, editor, source generator, tests), the ad family (`com.nexus.ads`,
`com.nexus.ads.levelplay`, `com.nexus.ads.admob`, `com.nexus.ads.bridge.nexus`), `com.nexus.firebase`,
`com.nexus.fsm`, `com.nexus.dots` and `com.nexus.iap.unity`. Also checked: the host harness, the stubs,
the samples, and the documents that describe them.

**Readers.** Seven readers, each in its own read-only worktree on `4b994a5`:

| Reader | Slice |
|---|---|
| A | DI and contexts |
| B | Signals and commands |
| C | Services and models |
| D1 | Code generators, build validation, source generator, stubs, samples |
| D2 | Editor window, inspectors, overlay |
| E | Ad family, firebase, fsm, dots, iap.unity |
| G | Every test method |

Each reader returned candidates with `file:line`, a reproduction, the consequence, and the lists *suspected*
and *not examined*.

**Second check.** For every candidate, an independent verifier got only the location and the claim. It
traced the code on its own and searched the repository for anything that accepts the behaviour as intended.
For reader G, the second check covered a sample of 15.

**Auditor's step.** Where the code can run outside a device, the auditor ran a reproduction beside a control
run, so a probe that cannot see the effect is visible. Reproductions ran in one of three ways:
- a host probe, which is a copy of the harness project in a scratch folder;
- a temporary EditMode or PlayMode test in the development project, deleted after the run;
- a compile of the doc examples.

The auditor read the code instead where a run needs an SDK, a player build, a dialog or Play Mode with
started Roots.

**When a finding is listed.** The reader and the second check agree, and the auditor ran it or read it.
The **Evidence** column says which.

**Evidence location.** `Nexus/artifacts/audit-20261101/`, which is git-ignored and local like the other
gate artifacts:

## Performance

**Host harness on `4b994a5`.** Exit 0, no FAIL line. Of the checks that measure allocation, 21 print
`allocated=0`.

**Harness coverage.** There are 146 runtime files. The harness compiles 134. The other 12 are `InjectScanner`,
`NexusProfiler`, the two asset-load files, the five UI Toolkit stack files, `GcAllocationProbe`,
`MockAdNetworkAdapter` and `MockIapStoreAdapter`.

**Performance scope table.** Every check the package README's "Performance scope" table names exists. Its
threshold matches the README text: 0 B for GCA and SteadyState, at most 128 B for the others, at most 512 B
for F1.

**Hot paths the table does not list.** One host probe ran 5000 iterations of each path. The control
allocated 160000 B (32 B × 5000), so the probe sees allocation. Each path allocated 0 B, and each handler ran
5001 times:

| Probe | Path |
|---|---|
| P1 | A signal filter |
| P2 | A command and a subscriber |
| P3 | `FireThreadSafe` and the drain |
| P4 | `FireNextFrame` and the drain |
| P5 | `SecureObservableInt` |
| P6 | `SecureObservableFloat` |

These are host .NET numbers, not IL2CPP.

**Device setup.** `tools/nexus-comparison/run-unity.ps1` ran on `4b994a5`:
- **Identity:** `sourceCommit` `4b994a5`, working tree clean, `nexusDiSha256` `B18B0CC8…`.
- **Build:** Unity 6000.6.7f1, IL2CPP release player.
- **Device:** Xiaomi 2311DRK48G, Android 16, arm64-v8a.
- **Competitors**, pinned by commit: VContainer 1.19.0, Zenject 9.2.0, Reflex 14.4.0.
- **Workload:** core DI only. Per round: 200 000 operations for cached resolve, 20 000 for the transient
  three-node graph, 1 000 for register + build + first resolve. Seven rounds.

**Regression check against `17d31d0`.** Six launch rounds per configuration alternated `4b994a5` with the
APKs of `17d31d0` (`target-android-015`, `target-generated-android-007`). The criterion for a regression: the
new median above the old maximum. No Nexus scenario regressed.

| Configuration | Cached resolve | Transient graph | Register + build + first resolve |
|---|---|---|---|
| Reflection | −7.8% | −2.3% | +2.5% |
| Generated | −1.3% | −4.8% | +5.7% |

The competitors, whose code did not change, moved between −14% and +7%.

**Caveat.** The `17d31d0` APKs were built with Unity 6000.5.6f1 and the `4b994a5` APKs with 6000.6.7f1. The
two builds also differ in the editor and IL2CPP, so the competitors are the control for both the engine and
the drift between launches.

## Architecture

- **`InternalsVisibleTo` grants.** Every grant goes to one of:
  - a test assembly;
  - `com.nexus.fsm` and its editor (documented in `CLAUDE.md`);
  - another assembly of the same ad family (`Nexus.Ads.Core` → `Nexus.Ads.Unity`).

  No undocumented crossing.
- **Findings.** The architecture findings are in the table below:
  - the lifecycle reached through the parent container (#207);
  - startables routed to the root (#208);
  - the composite gap in `HasHandlers` (#220).

## Suspected, not verified

The readers' *suspected* candidates were not handed to the second check and were not filed. Each needs
evidence before it becomes an issue.

**A (DI and contexts)**
- `To().ToName()` overwrites the default binding; harness B4 locks part of it.
- `ExternalAdapter` skips `PostConstruct`.
- `PostConstruct` runs again on a pooled mediator.
- A `Configure` retried after a failure appends its registrations twice.

**B (signals and commands)**
- One closure and one string are allocated per drained async signal (README row 219).
- Command metrics ignore `MetricsEnabled`.
- A throwing strategy logs the failure three times.
- `s_ringBuffer` is outside `NEXUS_DEBUG`.
- The trace counters overflow at 2³¹.
- A throwing `ResetState` skips recovery.
- `Dispose` sweeps in O(N²).
- `NexusProfiler.CommandsExecuted` does not count composites.

**C (services and models)**
- `EncryptedStorage.SetFloat` does not use the "R" format.
- Reopening a screen in `UIManager` ignores its arguments.
- `EncryptedStorage.SetString(null)`.
- The `TickService` reference count without a domain reload.
- The mock store's `Restore` raises no `Changed`.
- `ObservableList` does not isolate its handlers.

**D1 (code generators and build validation)**
- A public type with several constructors gets neither a factory nor a link.xml entry.
- The stubs' `Object ==`, `Time` and `Instantiate`.
- A stale binder through load order.
- `ref`/`out` constructors.
- The guard's exception path.

**D2 (editor)**
- The Performance tab stops a recording the game started.
- `CloseTopScreenAsync`'s task is discarded.
- Setup's `NewScene` is additive while an untitled scene is open.
- LiveReload and a private method on a base class.
- The Context inspector's Resolved column constructs objects.
- Run Injection Now in edit mode.
- A type-name collision in `ScriptGenerator`.

**E (ad family and other packages)**
- A late `Opened` after the watchdog sets `_fullScreenOpen`.
- The AdMob reward after close has no grace period.
- The Firebase iOS plist.
- An iap.unity double grant.
- `NexusAdsBridge` connections are never removed.
- fsm with a token cancelled beforehand.
- `AdsBootstrap` subscribes twice.
- `AdRewardedButton`'s setter runs before `Awake`.
