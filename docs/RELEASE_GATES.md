# Release gates

A package version is tagged only when every gate below is green on the commit being tagged.
Each gate names its command and its latest measured result; a gate without a fresh result on
the release commit is red. Numbers here are replaced, never accumulated: earlier results are in this file's git history, and
`docs/archive/RELEASE_GATES-2026-10-28.md` holds the per-commit history from v0.5.0 until the cycle on `3271239`.

Latest full run: **2026-10-29**, every gate on commit `17d31d0` (#111, #112, #116, #117), Unity **6000.5.6f1**, Windows 11. It is the games' re-pin target, and the last one before v0.6.0: from it the package code is frozen, and `main` takes only fixes for bugs that a game's issue reports, each with its regression test (the owner's decision of 2026-10-28; #117, found by an external audit in the games' ad path, was the one exception, by the owner's decision of 2026-10-29; see Open work).
Not a tagged version: `package.json` stays 0.5.0 (tag **v0.5.0** = `8f19c20`) and everything since is Unreleased.
Result files are local and git-ignored, under `Nexus/artifacts/`.

## Policy

- A test exists to lock a behaviour that was wrong or can regress. Tests that restate the
  implementation, assert constants, or duplicate another test are removed, not added.
- Evidence is a result file or a log from the command above, dated and tied to a commit.
  "Verified" without that is not used in any document.
- Performance claims name the workload, platform, Unity version, competitor versions and the
  reproduction tool. Host benchmarks never stand in for device measurements.
